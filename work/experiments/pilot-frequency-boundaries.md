# Граничные значения частоты пилота

9 ноября 2026, локальный стенд `localhost:8081`, модель `tuva-frequency-v1`, артефакт `7a33b4bf…`. Проверено поле частоты первой редактируемой связи на desktop Chromium; другие поля и сезонные комбинации не проверялись.

| Значение | Интерфейс | API `manual:0`, лето |
| --- | --- | --- |
| 0 | Ошибка, кнопка расчёта недоступна | 422 |
| 1 | Ошибки нет, кнопка доступна | 200; время первой пары 18,0951 ч |
| 28 | Ошибки нет, кнопка доступна | 200; время первой пары 5,2433 ч |
| 29 | Ошибка, кнопка расчёта недоступна | 422 |
| Пусто | Ошибки нет, кнопка доступна | 200 без параметра частоты; первая пара 18,0951 ч |

Пустое поле приводит к отправке `{"edge_id":"manual:0","enabled":true}` без `frequency_per_week`. Исходная частота остаётся в модели; это поведение отличается от явного нуля и само по себе не является ошибкой расчёта. Однако пустое поле визуально не говорит, что применится частота из источника: рядом видна подсказка с исходным значением, но явной связи с очисткой поля нет. Пользователь может ожидать, что число неизвестно или что рейсы отключены. Риск — неверная интерпретация сценария.

Варианты решения для обсуждения: явно подписать пустое значение как «использовать исходную частоту» и сохранить текущее поведение, либо требовать заполненное поле для включённой редактируемой связи. Второй вариант должен отдельно учитывать исходные связи с неизвестной частотой и условными допущениями; автоматическое превращение пустого значения в ноль недопустимо. Исправления интерфейса не вносились.

Дополнительно существуют автоматические проверки API на 0, 29, булево значение, дробь и строку в `backend/tests/unit/controller/test_pilot_routes.py`; здесь они не перезапускались. Ручные проверки API использовали `GET /api/v1/pilots/tuva` для актуальных версий и `POST /api/v1/pilots/tuva/evaluate` для указанных значений. Предварительная браузерная попытка с неверно указанным названием ссылки была прервана, успешная выполнена с реальной локализованной меткой.
