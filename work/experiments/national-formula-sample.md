# Расширенная проверка формулы Hansen

Дата: 2026-11-09, feat/model-validation, HEAD bad747d. Команда из корня: `uv run python work/experiments/national_formula_sample.py > work/experiments/national-formula-sample-results.json`. Вход — data/casechamp.duckdb, соединение read-only; новая запись в продуктовые витрины не производится.

Из каждого из 82 регионов выбраны пункт с максимальным населением и пункт с минимальным положительным населением; дополнительно один пункт без маршрута к рынкам в базовом дорожном сценарии, если он есть. При совпадении выбора точка включается один раз. Итого 215 уникальных пунктов и 1075 комбинаций «пункт × сценарий»; среди последних 236 без найденных рынков. Выборка целенаправленная, не случайная и не репрезентативная оценка ошибок всей совокупности.

По 144322 сохранённым парам «пункт — город» и весам из market_cities независимо от SQL агрегатора вычислены суммы Python `math.exp` и `math.fsum` для половинных периодов 1, 2 и 4 часа: 3225 сравнений; отклонений выше относительного 1e-10 или абсолютного 1e-6 нет. Для всех 1075 строк также проверены число найденных рынков, конечность и неотрицательность входных времён, уникальность записей, а также нормировка двухчасового показателя на общую базу с допуском 1e-10 относительным или 1e-8 абсолютным. Нарушений нет. Скрипт завершает работу с ненулевым кодом при ошибке и сохраняет подробности в JSON.

Проверка независимо повторяет арифметическую формулу, но использует те же записанные времена, население и выбранную базу. Она не проверяет географическую правильность путей, валидность сезонности, отсутствие пропущенных рынков в исходной таблице или правильность экономической интерпретации. Отсутствие найденных путей в рамках модели не доказывает реальной изоляции.

Первый запуск не выполнился: DuckDB 1.2.2 не принял тип строки pandas при регистрации временной таблицы. Передача списка кодов через явную строковую колонку Arrow устранила проблему; повторный запуск завершился успешно.
