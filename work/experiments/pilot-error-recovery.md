# Восстановление после ошибки пересчёта пилота

9 ноября 2026. Desktop Chromium, локальный стенд `localhost:8081`, существующий пилот. Автотест [pilot-recovery.spec.ts](../../frontend/e2e/pilot-recovery.spec.ts) задаёт 7 рейсов и один раз подменяет ответ POST `/api/v1/pilots/tuva/evaluate` на HTTP 503. Интерфейс показывает ошибку и не показывает результат 14,24; после снятия подмены кнопка «Повторить» выполняет настоящий запрос, отображает 14,24 и сохраняет введённую частоту 7.

`E2E_BASE_URL=http://localhost:8081 npx playwright test e2e/pilot-recovery.spec.ts`: 1 passed. `npx biome check e2e/pilot-recovery.spec.ts`: прошёл. Это проверка одной искусственной ошибки во время первого расчёта, не проверка всех сбоев или реального отключения сервера. Предварительная попытка создать тест с неверным путём остановилась без создания файла; затем команда повторена с правильным рабочим каталогом. Текущий черновой ZIP создан до добавления этого теста.

## Ошибка после успешного расчёта

Дополнен второй сценарий: после результата 14,24 ч для семи рейсов частота меняется на четыре, прежний результат отмечается устаревшим. При искусственном 503 старый результат исчезает и отображается ошибка. После повтора проверены реальный запрос с частотой 4, ответ 18,0951 ч и отсутствие предупреждения об устаревшем результате. Оба теста прошли: `E2E_BASE_URL=http://localhost:8081 npx playwright test e2e/pilot-recovery.spec.ts` — 2 passed; Biome для файла прошёл. Проверка касается одного типа искусственного отказа, не всех сбоев.

## Конфликт версий

В третьем desktop-тесте ответ первоначального GET пилота перехвачен, а версия артефакта заменена на старую тестовую строку; данные самого пилота не менялись. Последующий запрос на настоящий API вернул 409. Интерфейс показал ошибку; «Повторить» повторно загрузил настоящий GET, снял ошибку, после повторного ввода семи рейсов расчёт показал 14,24 ч. `E2E_BASE_URL=http://localhost:8081 npx playwright test e2e/pilot-recovery.spec.ts` — 3 passed; Biome для файла прошёл.

Замечание: при загрузке другой версии артефакта введённая частота сбрасывается с 7 на исходные 2. Это соответствует перемонтированию формы по версии, но сообщение о конфликте не предупреждает о потере внесённых параметров. Пользователю необходимо заново их ввести; возможное улучшение — предупредить об этом или безопасно перенести совместимые значения. Тест не имитирует все типы изменения схемы или данные нового реального артефакта.

## Повторная загрузка с прежней версией

На `localhost:8081` первый POST искусственно вернул 409 `stale_pilot_version`; после этого GET при нажатии «Повторить» получил от реального сервера тот же артефакт, что был загружен до сбоя. Ошибка после успешного GET осталась видна, введённое значение 7 сохранилось. Кнопка «Пересчитать» повторно отправила запрос на настоящий API, после чего 14,24 ч отобразились. Следовательно, пользователь не полностью заблокирован, но предложенное действие «Повторить» не устраняет сообщение в этом сценарии. Возможный случай — временная рассинхронизация ответов или откат версии; его частота в реальной инфраструктуре не оценивалась.

Предложение: после успешной перезагрузки того же артефакта явно сбрасывать состояние ошибки расчёта либо показывать действие повторного расчёта, сохраняя обработку ошибки самой перезагрузки и проверив гонки с новым запросом. Продуктовый код не менялся.

## Исправление повторной загрузки той же версии

Причина: сообщение относится к состоянию мутации расчёта, а повторная загрузка пилота не сбрасывала его при неизменной версии артефакта. Повторная загрузка теперь возвращает статус успеха; только после успешной загрузки и при той же ошибке состояние мутации сбрасывается. Если за время загрузки состояние расчёта изменилось, новый результат не сбрасывается. При ошибке загрузки сообщение остаётся.

До правки браузерный регрессионный тест воспроизвёл сохраняющееся сообщение. После правки: 5 сценариев восстановления и 3 конкурентных сценария на Vite `localhost:5188` с API `localhost:8081` прошли; `npm run verify` прошёл (36 правил, 375 unit-тестов, typecheck, lint, build). Сборка вывела предупреждение PostCSS об отсутствии `from`. Сначала dev-прокси ошибочно указывал на недоступный порт 8000; после указания API 8081 тесты повторены. В dev-режиме тест конфликта версий скорректирован для повторных начальных GET. Черновой архив создан до этой правки кода.

## Позднее обновление после нового расчёта

Добавлен браузерный сценарий: после искусственного 409 задерживается повторный GET пилота, запускается новый расчёт с частотой 7, и только затем возвращается GET прежней версии. Результат 14,24 ч остаётся видимым, старое сообщение об ошибке отсутствует. На Vite `localhost:5188` и API `localhost:8081` все 9 сценариев восстановления и конкурентных действий прошли; после уточнения ожидания завершения обработки GET новый сценарий повторно прошёл отдельно. Biome для теста прошёл с форматированием. Этот тест касается конкретного порядка запросов и не доказывает отсутствие всех гонок.
