# Восстановление хранилища 10.11.2026

Около 19:17 UTC загрузка `plexus_refresh_graph.ways__loading` получила
ClickHouse HTTP 500: filesystem create_directories, Input/output error.
Свободное место хоста упало до 460 MiB; журналы Docker показывают ошибки
записи виртуального диска vda и EXT4. Рабочие таблицы не обменивались.

Автопроверка отклонила удаление десяти временных исходников OSM до явного
разрешения пользователя. Расчёт RAI завершён с сохранением исходников.
Пользователь затем ответил: «Да, удалить временные OSM-файлы».
Удалено ровно десять файлов из `data/road-refresh/ways/`, 1 465 485 073 байта.
Перед удалением повторно сверены SHA-256 каждого файла, готового RAI и
манифеста графа. Контрольные суммы, URL, даты и манифесты сохранены.
`data/road-refresh/source-cleanup.json` содержит точный список.

После освобождения места Docker и ClickHouse продолжали зависать.
Запущен штатный `docker desktop restart --timeout 60`; тома и контейнеры
не удалялись. Проверка таблиц после восстановления ещё предстоит.
Параллельно расчёт `access_russia.py` использует отдельный новый граф и
временную DuckDB; он не зависит от доступности Docker.

Мягкий перезапуск истёк по тайм-ауту. `docker desktop stop --force --timeout 30`
и `docker desktop start --timeout 60` восстановили движок. Все существующие
контейнеры снова запущены. CHECK TABLE успешно проверил 83 таблицы проекта,
включая рабочий граф, матрицы, атлас и историю заданий; результат сохранён в
`storage-checks.json`. Счётчики рабочих таблиц совпали со снимком до сбоя.
Повреждённые незавершённые части найдены в staging и системных журналах;
новые ways загружены заново, существующие рабочие таблицы не заменялись.
