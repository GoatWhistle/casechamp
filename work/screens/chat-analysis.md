## Behavior and ownership

The existing chat receives an `analysis` event from start/read/control tools. It renders a
live job card, verified ranking and a streamed commentary in the same message. No navigation URL
is returned by analysis tools. Sorting is descending delta for improvements and ascending delta
for criticality, then OSM way ID. Values are absolute index points, with affected population and
criticality isolation counts; notes preserve base network and best-checked limitations.

Waiting for road calculations does not keep a model stream open. A completed/paused compatible
batch triggers a separate chat request carrying only its analysis ID. The Chat use case loads
saved results, replaces client prompt/history and supplies the ten leading results. Gateway
registers no tools for this request. TanStack mutation scope serializes chat streams. Repeated
polls do not repeat commentary; failures preserve the table and expose retry. In-flight commentary
aborts on unmount; server-side calculations continue. Message resize follows the bottom only while
the user has not scrolled away. Source references survive in chat history.

Pending: progress/no verified rows. Partial: table adds real results. Finished: comment streams.
Failed/cancelled/interrupted: retained rows/status, no automatic completion claim. Query and model
errors are separate. Sources/parameters use existing Disclosure. Existing design tokens and
DataTable are reused. No new animation or mobile scope.
