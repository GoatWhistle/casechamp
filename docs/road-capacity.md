# Полосность и время проезда по дороге

> Метод `road-capacity-v1` связывает характеристики дороги со временем движения.
> Задержка от загрузки применяется только к подтверждённому часовому потоку.
> При неизвестном потоке расчёт использует свободное движение.

Связанные методы: [Hansen](indices.md), [экономическая оценка](economic-appraisal.md), [API](api.md).

---

## Характеристики дороги и время

Одна функция [дорожной стоимости](../backend/src/app/domain/road_cost.py) используется
при сборке расчётного графа и при изменении выбранных дорог в сценарии.

| Вход | Влияние |
| --- | --- |
| Класс дороги | Задаёт модельную скорость свободного движения |
| Покрытие | Для непокрытых дорог применяется коэффициент 0,7 |
| Полосность | Определяет модельную пропускную способность |
| Ограничение скорости | Ограничивает модельную скорость сверху |
| Проектная скорость в сценарии | Явно задаёт новую скорость свободного движения и её предел |
| Подтверждённый часовой поток | Добавляет задержку в зависимости от отношения потока к пропускной способности |

Скорости по классам и коэффициент покрытия являются допущениями, перечисленными в
[параметрах модели](../backend/src/app/domain/road_profiles.py). Например, для `track`
на грунте используется `20 × 0,7 = 14 км/ч`, для `motorway` на асфальте `90 км/ч`
при отсутствии более низкого ограничения. Поэтому смена класса и покрытия меняет
время даже без замеров трафика. Одно расширение дороги при неизвестном потоке
сохраняет прежнее время свободного движения.

## Магистраль и просёлочная дорога

Для условного пути в 100 км без других ограничений модель даёт:

| Дорога | Скорость | Время | Вес одного рынка в Hansen с полураспадом 2 часа |
| --- | --- | --- | --- |
| Грунтовая track | 14 км/ч | 7,14 часа | 0,084 |
| Асфальтовая motorway | 90 км/ч | 1,11 часа | 0,680 |

Вклад одного и того же рынка во втором случае примерно в 8,1 раза больше.
Это пример формулы, а не прогноз для конкретной трассы: реальные пути имеют
перекрёстки, ограничения и альтернативы. При расширении с двух до четырёх полос
без подтверждённого потока оба времени свободного движения остаются прежними.

## Пропускная способность и задержка

При отсутствии полосности принято по одной полосе в допустимом направлении.
Если направления двусторонней дороги описаны раздельно, используется меньшее
число полос из двух направлений. При известном общем числе без распределения
применяется целое число полос половины проезжей части. Для одной общей физической
полосы используется отдельный признак совместного движения двух направлений.

Пропускная способность принята равной `1800 × n` приведённых автомобилей в час,
где `n` обозначает число полос представительного направления. Для общей одиночной
полосы 1800 относится к сумме обоих направлений. Значение 1800 является
**допущением, не результатом калибровки**. Противоречивые или условные теги не дают
известной пропускной способности до разрешения неоднозначности.

Для подтверждённого потока применяется функция:

`t = t₀ × [1 + 0,15 × (q / C)⁴]`,

где `t₀` обозначает свободное время, `q` часовой поток, `C` пропускную способность
в тех же единицах. Эта форма BPR приведена в [методическом примере FHWA](https://ops-dr.fhwa.dot.gov/publications/fhwahop21014/chap4.htm).
Параметры здесь не откалиброваны для каждого российского участка. Формула не
воспроизводит образование и распространение очередей, работу светофоров и изменение
спроса после реконструкции.

Подтверждение требует источника, периода наблюдений, подходящих единиц и привязки
к участку. Суточные автомобили и приведённые автомобили в час не взаимозаменяемы.
Наблюдение только в сечении не назначает поток всем участкам одноимённой трассы.
При расширении подтверждённый абсолютный поток сохраняется; меняется `C`.
Число жителей и годовые поездки из денежной оценки не заменяют `q`.

## Параметры сценария

В панели сценария выберите «Полосы и покрытие». Можно изменить общее число полос
каждого выбранного объекта OSM, класс, покрытие и проектную скорость. Пустые поля
сохраняют исходное значение. Полосы двух раздельных проезжих частей относятся к
разным объектам OSM и задаются для них отдельно.

Режим «Множитель скорости» сохраняет прежний ручной способ: 1 оставляет время,
0 закрывает дорогу, положительный множитель меняет время обратно пропорционально.
Совместить ручной множитель, отличный от 1, с изменением профиля нельзя.

Результат содержит `road_cost_method` и `road_cost_notes`. Карточка поясняет отсутствие
экономии времени от изменения полосности там, где часовой поток не подтверждён.
Принятая ширина и ручное время новой связи также отмечаются отдельно.

Новая связь по двум узлам сохраняет явно введённое время `travel_hours`.
Геометрия между её концами не является проектом трассы, а её длина для грузовой
оценки автоматически не назначается.

## Пересчёт результатов

Новые времена поступают в матрицы поездок, из которых считаются Hansen, Harris,
пороговая доступность, удалённость, ARIA и распределение доступности жителей.
В сравнении сценариев нормировка общей базы фиксирована. RAI использует близость
к всесезонной дороге и может остаться прежним при расширении существующей геометрии.
Неравенство доступности также не обязано уменьшаться при каждом проекте.

Маршрутизация сохраняет симметризованные дорожные связи действующей модели.
Представительная пропускная способность не заменяет направленную маршрутизацию
с проверкой всех запретов движения. Результат описывает потенциальную доступность
в принятой сети, а не прогноз навигатора для конкретного часа.

## Подготовка данных

Из корня проекта с экспортированными настройками ClickHouse:

```bash
set -a
source .env.analytics
set +a
PYTHONPATH=backend/src:etl .venv/bin/python -m road_capacity all --workers 6
```

Команда готовит отдельные расчётные таблицы и сохраняет состояние в `data/road-capacity`.
Она закрепляет источники, строит веса, матрицы, индексы и представления атласа.
Сама команда не переключает работающий API на новый снимок. Версии и проверки
этапов сохраняются вместе с результатом.

Изменение схемы заданий перед обновлением API:

```bash
PYTHONPATH=backend/src:etl backend/.venv/bin/python -m analytics.migrate_road_capacity
```

После завершения подготовки проверка снимка запускается отдельно:

```bash
PYTHONPATH=backend/src:etl .venv/bin/python -m road_capacity.validate
```

Для включения API должен быть остановлен, а очередь заданий пуста:

```bash
PYTHONPATH=backend/src:etl .venv/bin/python -m road_capacity.activate
```

После команды API запускается с обновлённым кодом. Журнал `data/road-capacity/activation.json`
содержит UUID таблиц и шаги переключения. Прежние таблицы остаются в базах
`plexus_capacity_*`; их нельзя удалять, пока нужен откат. При остановленном API
`python -m road_capacity.activate --rollback` возвращает прежние таблицы.
Для повторного запуска используются исходный каталог контрольных точек и тот же
журнал. Новый каталог поверх занятых промежуточных баз не создаёт новый снимок.

Старые задания сохраняют параметры и прежний метод. Новые поля профиля необязательны.
Кеш расчётной базы различает версии дорожной стоимости.

## Национальный пересчёт 11 ноября 2026 года

Пересчитаны 155 747 населённых пунктов в трёх сценариях: 467 241 строка.
Расчётные таблицы сохраняют все 84 исходных региона, публичный атлас содержит
82 региона и 246 записей. В графе 4 301 210 дорожных объектов. Подтверждённых
часовых потоков для них пока нет, поэтому задержки от загрузки не добавлены.

Ограничения скорости присутствуют у 240 516 объектов, на 62 182 они снижают
модельную скорость. Средний Hansen по населению 82 регионов в сценарии road
изменился с 99,1273 до 98,4536 при фиксированной шкале. Рост индекса
от простого наличия дополнительных полос в этот результат не заложен.

[Протокол проверки](results/road-capacity-validation.json) содержит проверки
сохранности топологии, исходников, покрытия профилями и состава атласа.
Пять формул независимо проверены по матрице для 96 населённых пунктов.
252 региональных значения совпали с расчётом общего маршрутизатора, максимальное
расхождение Hansen составило 3,6 × 10⁻¹².
[Сравнение по регионам и сезонам](results/road-capacity-regional-comparison.csv)
сохраняет исходное и новое значение каждого региона.


## Проверка через работающий API

11.11.2026 выполнены два сценария для пяти существующих дорожных объектов
на маршруте из Волжского в Волгоград. Это технический пример, не проект
переустройства городского проспекта в магистраль.

| Сценарий | Изменение Hansen региона | Время пассажирской поездки |
| --- | --- | --- |
| Только четыре полосы на выбранных объектах | 0 | 26,94 минуты до и после |
| Полосы, асфальт, класс motorway и проектная скорость 90 км/ч | +0,0841 пункта | 26,94 минуты до, 24,29 после |

Для проверки денежной формулы заданы условные 100 000 пассажирских поездок в год
по 300 руб./час и 1000 грузовых рейсов по 500 руб./машино-час и 15 руб./км.
Второй сценарий дал 1 323 939,26 руб. пассажирской и 22 065,65 руб. грузовой
годовой выгоды. Пробег грузового пути сохранился: 25,881 км. В сценарии
одной полосности обе годовые выгоды равны нулю. Капитальные затраты и содержание
считаются отдельно; нулевая выгода не означает нулевые затраты проекта.

[Протокол сквозного расчёта](results/road-capacity-live-validation.json) содержит
идентификаторы заданий и исходные/новые времена. Годовые потоки и ставки являются
допущениями проверки. Они не подтверждают часовую интенсивность этих участков.


[Итоговые проверки](results/road-capacity-checks.json): 300 backend unit-тестов,
45 интеграционных тестов, 448 frontend-тестов и сборка прошли. Три desktop E2E
проверили расчёт и сохранение экономической оценки, отсутствие эффекта полосности
без потока и доступность редактора. Клавиатура и axe проверены, интерфейс осмотрен
при ширине 1440 px. Все 14 прежних заданий остались доступны.
