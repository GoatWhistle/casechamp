# Сценарная нагрузка от населения и жилой застройки

Основной пользовательский сценарий: [муниципальная доступность и дорожные изменения](municipal-accessibility.md).
Автоматический поиск новых дорог удалён; [сохранённые эксперименты](network-development.md) доступны только для чтения.

> Расчёт создаёт матрицу автомобильных поездок и распределяет её по дорожной сети. Один и тот же спрос используется для исходной сети и каждого проекта. Результаты описывают условную нагрузку при сохранённых допущениях.

**Читайте, если** сравниваете небольшие дорожные улучшения · **Связано:** [Полосность](road-capacity.md) · [Перенос потока при закрытии](traffic-diversion.md)

## Откуда берутся жители и поездки?

Исходная численность жителей берётся из населённых пунктов расчётного снимка ClickHouse. Жилые здания OSM уточняют размещение этих жителей: вес здания равен площади контура, умноженной на число этажей. При неизвестной этажности используется один этаж. Тип здания должен явно указывать жилое назначение. Этот вес обозначен `residential_m2_proxy` и не считается измеренной жилой площадью.

Здание относится к ближайшему населённому пункту в пределах 5 км. Его вес нормируется на известное население этого пункта. Суммарная численность сохраняется. Для пунктов без подходящих зданий остаётся исходная привязка. Дома привязываются к узлам местных дорог не дальше 1 км. Фактический подъезд и препятствия между домом и узлом отдельно не проверяются.

Данные зданий: © OpenStreetMap contributors, ODbL 1.0.

Для всей РФ сборщик последовательно обрабатывает [выгрузки Geofabrik](https://download.geofabrik.de/russia.html). Он сохраняет URL, время OSM-снимка, SHA-256 и число извлечённых зданий. После проверки Parquet временный скачанный PBF удаляется. В проверенной коллекции среза 11 ноября 2026 года извлечено 6 443 907 записей; после удаления повторяющихся OSM ID остаётся 6 404 792 объекта. Это объекты с явно указанным жилым типом, полнота учёта всех физических домов не установлена. Повторный запуск пропускает проверенные округа. При объединении файлов повторяющиеся идентификаторы зданий удаляются.

Дома группируются в пространственные зоны. Размер ячейки увеличивается до заданного бюджета зон, при этом разные компоненты сильной связности не объединяются. Представитель зоны получает всю её численность. Время относится к пути между узлами зон; подъезды от домов к этим узлам опущены. Внутризональные поездки по дорогам не рассчитываются; такая агрегация подходит для предварительного сравнения межзональных связей.

Число машин, выезжающих из зоны за расчётный час:

`население × поездки человека за сутки × доля межзональных поездок × доля автомобиля × доля суточных поездок в этом часу / людей в автомобиле`.

| Параметр | Начальное допущение |
| --- | ---: |
| Поездок человека за сутки | 2 |
| Доля межзональных поездок | 0,25 |
| Доля автомобиля | 0,5 |
| Людей в автомобиле | 1,5 |
| Доля суточных поездок в расчётном часу | 0,1 |
| Полупериод привлекательности назначения | 1 час |
| Максимальное исходное время межзональной поездки | 4 часа |

Направления выбираются пропорционально населению зоны назначения с экспоненциальным уменьшением веса по исходному дорожному времени. Население служит приближением привлекательности, сведений о рабочих местах эта модель не добавляет. Если в пределах временного профиля нет достижимых внешних назначений, потенциальный спрос сохраняется отдельным числом. Поездки на сотни часов не возникают из-за отсутствия близких вариантов. Это профиль региональных автомобильных перемещений; дальние поездки требуют отдельного профиля спроса. Грузовые перевозки в эту версию не входят.

Параметры можно передать через `--demand-parameters`. Коэффициенты низкой, базовой и высокой нагрузки по умолчанию равны 0,7, 1 и 1,3. Они масштабируют общую матрицу, а исходная сеть и проекты сравниваются при одном коэффициенте. После строительства спрос автоматически не увеличивается.

## Как машины распределяются по дорогам?

Используются исходные ориентированные рёбра снимка. Время свободного движения восстанавливается по длине и свободной скорости из дорожного профиля. Прежняя задержка от потока повторно не прибавляется.

Потоки всех пар рассчитываются совместно. На каждой итерации ищутся быстрые пути с текущими задержками, потоки суммируются на общих рёбрах и усредняются методом последовательных средних, MSA. Параллельные рёбра сохраняются, выбор между ними пересчитывается при изменении загрузки. Это стандартная схема статического распределения; [документация AequilibraE](https://www.aequilibrae.com/docs/python/v1.6.0/traffic_assignment/assignment_procedures.html) описывает такие алгоритмы и функции задержки.

Время ребра: `t = t0 × (1 + 0,15 × (q/C)^4)`. Здесь `q` означает назначенный спрос в приведённых автомобилях за час, `C` — модельную способность. Все поездки этой версии считаются легковыми с коэффициентом приведения 1. При общей единственной полосе учитывается сумма обоих направлений. При асимметричных полосах сохраняется консервативная представительская способность исходного дорожного профиля.

Отчёт содержит относительный разрыв между стоимостью назначенного потока и текущих кратчайших путей, число итераций и достижение допуска. Сравнение экономии времени выводится только при сходимости обоих вариантов и одинаковом объёме обслуживаемого спроса. Необслуженный спрос показан отдельно.

Превышение `q/C > 1` означает спрос сверх способности. Статический расчёт не определяет длину очереди или фактически прошедшее за час число машин. Очереди во времени, светофоры, повороты, обратное распространение затора и изменение спроса не моделируются.

## Какие изменения разрешены?

CLI `python -m synthetic_traffic run` принимает выбранные изменения существующих
дорог: `capacity` и `closure`. Команда автоматического подбора `candidates` удалена.
Новые соединения, открытия, пакеты и самостоятельное повышение скорости не принимаются.
Сценарии используют неизменный спрос. Географическую пригодность расширения
проверяют отдельно; изменение пропускной способности не означает согласованное строительство.

Пример проекта: `{"kind": "capacity", "way_ids": [123], "extra_lanes": 1}`.
Идентификатор дороги должен существовать в подготовленном снимке.

CLI сравнения остаётся вычислительным инструментом. Он не устанавливает наличие
заранее подготовленной национальной базы нагрузки или готовность муниципальных диффов.
Полный список параметров доступен через `python -m synthetic_traffic run --help`.
