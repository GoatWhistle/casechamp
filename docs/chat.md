# Чат рядом с картой

Чат отвечает по данным атласа для всех доступных регионов. Выбранный регион, сезон,
режим транспорта и показатель передаются с каждым вопросом. Агент может читать
региональные показатели, искать территории, просматривать связи, населённые пункты
и источники. При подключённом расчётном графе агент запускает дорожные, железнодорожные
и авиационные сценарии. Исходные данные при этом сохраняются.


## Локальный запуск

На сервере нужна действующая авторизация провайдера; [настройка](dependencies.md).
Сервер использует её локально; ключи и токены не передаются браузеру.

Из корня проекта с настроенным ClickHouse:

```bash
set -a
source .env.analytics
set +a
cd backend
uv sync
GRAPH_DIR=../data CHAT_ENABLED=true ROAD_WORKERS=6 uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8007
```

Во втором терминале:

```bash
cd frontend
npm ci
API_URL=http://127.0.0.1:8007 npm run dev -- --host 127.0.0.1 --port 5187
```

Откройте http://127.0.0.1:5187/. Справа находятся вкладки «Чат» и «Сводка».
Enter отправляет вопрос, Shift + Enter добавляет строку. Кнопка остановки отменяет
запрос. Плюс создаёт новый разговор. История сохраняется в localStorage браузера;
серверу передаются последние 12 завершённых сообщений.


## Устройство

Pydantic AI 2.66.0 управляет инструментами и диалогом. SDK провайдера версии 0.167.0
проверяет и обновляет состояние локальной авторизации через app-server.
`OpenAICodexModel` является реализацией Responses-модели Pydantic AI и отправляет
запросы в backend провайдера. Модель зафиксирована: `gpt-6.1-sol`, reasoning effort `low`.
Это внутренний серверный шлюз, отдельный публичный `/v1/responses` не публикуется.
SDK не запускает coding-agent thread и не предоставляет модели shell или файловые инструменты.

`POST /api/v1/chat` принимает `prompt`, `history` и `context`. Ответ передаётся
в NDJSON: `status` сообщает действие, `delta` содержит фрагмент текста, `done`
завершает ответ, `table` передаёт строки и колонки, `chart` ссылается на таблицу, `error` содержит безопасный код ошибки. Отсутствие `done` означает
обрыв. Отключена буферизация ответа; отмена закрывает генераторы и соединение с моделью.
Один процесс обслуживает до трёх ответов одновременно; ожидание свободного места
ограничено 120 секундами. Лимиты: 4000 символов вопроса, 12 сообщений истории,
16 запросов к модели, 24 вызова инструментов, 180 секунд на ответ после очереди.

По умолчанию `CHAT_ENABLED=false`: атлас работает без авторизации и модели,
а чат сообщает, что он не включён. Ошибки авторизации и сети не подменяются
выдуманным ответом. Локальный режим не предназначен для общего стенда с личной подпиской.


## Интерфейс и источники

Композиция адаптирована из [GoatWhistle/rwb](https://github.com/GoatWhistle/rwb),
снимок `b24b3d5ab08637b6d46fa3952a45a076ba342c57`: компактная шапка, вопросы
в пузырях справа, Markdown-ответы, список действий и округлое поле ввода.
Сохранены компоненты, шрифт и цветовые токены Plexus. [Лицензия образца](licenses/rwb-MIT.txt).
Из rwb также адаптированы нормализация текста и схема аналитических блоков:
таблица приходит из инструмента, а график ссылается на её идентификатор и колонки.
Модель выбирает представление, но не передаёт свои числовые значения в график.
Поддержаны столбчатые сравнения регионов и населённых пунктов, таблицы связей,
раскрытие строк и исходные данные. Голосовой ввод не переносился.

Markdown отображается через `react-markdown` и `remark-gfm`: заголовки, списки,
чек-листы, цитаты, код и таблицы. Источники и параметры вынесены под раскрытие;
оговорки о неполноте данных и пояснения после описания среза остаются в ответе.
Кодовые блоки сохраняются при нормализации. Для таблиц доступна горизонтальная прокрутка.

HTML и внешние изображения отключены.
Ссылки используют безопасное преобразование URL библиотеки и `rel=noreferrer`.

[Провайдер, авторизация и документация SDK](dependencies.md).


## Формулы и действия на карте

Математика отображается через `remark-math` и KaTeX в доступном MathML. Поддержаны
`$…$`, `$$…$$`, `\(…\)`, `\[…\]` и прежние записи вида `(H_i=\sum_j M_j f(c_{ij}))`.
Код, ссылки и обычные текстовые скобки сохраняются; формулы появляются по мере стрима.
KaTeX работает без доверенных HTML-команд, с ограничением раскрытия макросов.

Инструмент `present_atlas(kind=map)` передаёт событие `map`: `focus`, `reset`, `zoom_in` или
`zoom_out`. Для фокуса сервер проверяет от 1 до 30 идентификаторов регионов и наличие
геометрии; координаты от модели не принимаются. Один регион выбирается также в сводке
и URL. Несколько регионов выделяются вместе и помещаются в общий кадр. Масштаб можно
изменить на один шаг или вернуться ко всей стране. В ответе есть кнопка повторного
перехода. Названия и идентификаторы строк предыдущих таблиц передаются с историей,
чтобы продолжение «покажи эти регионы на карте» сохраняло контекст.

Для населённого пункта агент находит точный ID через `query_atlas(kind=places)` или
`query_atlas(kind=settlements)` и вызывает `present_atlas(kind=settlement, settlement_id=...)`.
Сервер получает координаты из хранилища и передаёт `focus_settlement`. Карта приближается
до масштаба 12, ставит отметку с названием и выбирает родительский регион в сводке и URL.
Одноимённые пункты различаются по региону и ID. Координаты от модели не принимаются.
Повторная кнопка возвращает к пункту после перемещения карты. При сокращении движения
переход происходит сразу.

Для участка дорожного графа используется тот же инструмент: `present_atlas(kind=road,
way_ids=[...])` принимает ID проверенных дорог из рейтинга, выбранных дорог или видимой
области. `selection_ids=[...]` принимает найденные коридоры и мосты. Сервер получает
геометрию из хранилища и передаёт `focus_road`. Карта выделяет участок красным и
приближает его целиком с учётом открытой панели чата, до масштаба 16 для коротких дорог.
Повторная кнопка возвращает к участку. Новый расчёт для показа дороги не запускается.
Пустая, неизвестная или некорректная геометрия возвращает ошибку инструмента.

Примеры: «Покажи Тыву на карте», «Выдели Тыву и Республику Алтай вместе»,
«Приблизь Александровское в Ставропольском крае», «Вернись ко всей стране».
Изменение сезона через агента пока не подключено.


## Доступные расчёты

Агент проверяет `query_atlas(kind=capabilities)` и выбирает доступный расчёт.
Для развития дорог используется один вызов `calculate_scenario(kind=traffic_development)`.
Цель задаётся через `objective`: связанность, транзит или разгрузка. Территория,
проверенные предложения и эффект описаны в разделе [развития сети](#развитие-сети-с-расчётным-трафиком).

`find_transport(kind=road_viewport)` показывает существующие дороги видимой области.
`calculate_scenario(kind=network)` меняет каталожные транспортные связи, включая
ЖД, авиацию и сезонные сообщения. Закрытие найденной дороги или моста использует
`kind=close_selection`; критичность дорог оценивает `kind=road_analysis` с
`mode=criticality`. Чтение и отмена задания доступны через `manage_calculation`.

`query_atlas(kind=capabilities)` получает версию графа и дорожного метода от работающего
исполнителя. Ответ указывает, входят ли магистральные ЖД и авиация в базовый сценарий
`road`. Это зависит от модели; внутреннее имя сценария само по себе состав сети не задаёт.

## Рейтинг дорог в сообщении

`calculate_scenario(kind=road_analysis, mode=criticality)` передаёт задание событием
`analysis`. Чат показывает ход проверки и таблицу готовых результатов в том же
сообщении. Дороги упорядочены по потере индекса при закрытии; изменение указано
в пунктах индекса. Население затронутых пунктов не обозначает измеренный поток транспорта.
Чтение использует `manage_calculation(kind=status, calculation_type=analysis)`;
продолжение проверки критичности и отмена используют тот же инструмент.
Сохранённые рейтинги улучшений доступны для чтения; новые предложения рассчитывает
единый поиск развития сети.

После завершения порции проверок (`paused`) или всего задания (`completed`) чат сам
запрашивает потоковый комментарий LLM под таблицей. Сервер читает сохранённые результаты
по ID; числовые данные из запроса клиента для комментария не принимает. Этот запрос
не содержит инструментов запуска расчётов. При ошибке комментария таблица остаётся,
а кнопка повтора запрашивает только комментарий. Пока страница открыта, повторные
опросы одной завершённой порции не вызывают модель снова. При закрытии чата запрос
комментария отменяется; расчёт продолжает работать на сервере.

## Новые и сохранённые разговоры

Кнопка «Мои чаты» открывает небольшой список разговоров с поиском и датами.
Название берётся из первого вопроса, активный разговор отмечен галочкой. Кнопка
«Новый разговор» открывает пустой чат и сохраняет предыдущий. Повторное нажатие
не создаёт несколько пустых разговоров.

Переписки, черновики, таблицы, ссылки на расчёты и готовые комментарии сохраняются
в текущем браузере. Они восстанавливаются после перезагрузки страницы. Между
устройствами история не синхронизируется. При недоступном хранилище или исчерпанной
квоте чат сообщает об ошибке и оставляет содержимое открытой вкладки.

Во время ответа можно переключиться на другой разговор: поступающие части ответа
останутся в исходном чате. Запросы к модели выполняются по очереди. Открытие старого
разговора не повторяет команды камеры и не запрашивает уже сохранённый комментарий
LLM. Если потоковый ответ прервала перезагрузка, сохранённая часть остаётся с пометкой
об остановке. Незавершённый комментарий можно повторить кнопкой в его блоке.

В списке разговоров кнопка с корзиной удаляет выбранный чат после подтверждения.
Удаляются его сообщения и черновик; формирование ответа останавливается. Серверные
расчёты остаются в истории сценариев. После удаления последнего разговора открывается
пустой чат. При смене разговора выделения прежнего расчёта убираются с карты. Их можно
вернуть кнопкой «Показать участок на карте» в сохранённом сообщении. В легенде доступны
переключатель «Дорожный граф» и кнопка «Убрать выделение с карты».

При ошибке запроса сервер записывает последний этап, тип исключения, HTTP-статус
провайдера и доступную причину ошибки инструмента. Полный ответ провайдера, история
чата и данные авторизации в эту запись не входят.

## Закрытие нескольких мостов

`find_transport(kind=bridges)` ищет мосты около населённого пункта по признаку `is_bridge`
и геометрии сохранённого графа. Можно указать область после запятой, радиус до
50 км и фильтр по названию моста или номеру дороги. Ответ содержит варианты,
реальные OSM-идентификаторы, расстояния, длины и границы геометрии.

Связанные мостовые участки объединяются. Параллельные проезжие части с одинаковыми
названием, номером дороги и классом объединяются при совпадении концов с допуском
до 80 м. Это геометрическое правило: мосты с разной разметкой OSM могут остаться
отдельными вариантами. Среди результатов бывают путепроводы; близость к поселению
сама по себе не подтверждает выбор нужной переправы.

`calculate_scenario(kind=close_selection)` принимает выбранные варианты одним списком и закрывает
объединение их участков в обоих направлениях. На каждый регион поиска запускается
один расчёт совместного эффекта. Для межрегиональной переправы поиск нужен со
стороны обоих регионов. Остальные дороги и исходные данные не изменяются.
Карточка в чате показывает выбранную геометрию и ход расчёта, а затем результат.
Длина в ответе инструмента суммирует OSM-участки, включая параллельные проезжие части.


## Навыки аналитика

В начале ответа модели доступны два инструмента: `load_skill` и `query_atlas`.
Основная инструкция содержит роль и каталог пяти навыков. Агент загружает подходящие
навыки по смыслу вопроса. После загрузки транспортного или экономического навыка
появляются `find_transport`, `calculate_scenario` и `manage_calculation`. Навык
представления добавляет `present_atlas`. Полный набор ограничен шестью инструментами.

Тексты остальных навыков и схемы скрытых инструментов в запрос не добавляются.
Несколько навыков можно использовать вместе. Загруженный набор относится к одному
ответу и не передаётся другому пользователю или следующему запросу.

| Навык | Задача |
| --- | --- |
| `interpret-accessibility` | Объяснение индексов, покрытия и сравнение регионов |
| `economic-assessment` | Эффект транспортного сценария, затраты и экономические показатели региона |
| `road-scenarios` | Поиск дорог и мостов, последствия закрытия и критичность |
| `settlement-connectivity` | Существующие маршруты между выбранными пунктами |
| `traffic-development` | Развитие дорог: связанность, транзит и разгрузка |
| `rail-air-scenarios` | ЖД, авиация, изменение времени и закрытие связей |
| `present-atlas` | Таблицы, графики и действия на карте |

Навыки поставляются с backend в `app/adapter/chat/skills/*/SKILL.md`. Инструмент
загружает только имена из этого каталога, без произвольного доступа к файлам.
Пользовательские названия, заметки источников и прежние сообщения остаются данными.

Вопрос об экономическом эффекте транспорта требует сценария и исходных потоков.
Выручка компаний описывает учтённый бизнес и не заменяет такой расчёт. Агент может
прочитать сохранённую оценку либо запросить недостающие параметры для новой.
Для ВРП и доли в ВВП нужны сопоставимые официальные агрегаты, которых сумма выручки
компаний не даёт. Полнота путей для входного населения также не доказывает полноту
дорожной сети или расписаний.

## Сценарии ЖД и авиации

`find_transport(kind=services)` показывает связи расчётного снимка и отмечает возможное усечение
списка. `query_atlas(kind=links)` читает отдельный каталог с источниками и частотами. Наличие пары
в расчётной матрице не подтверждает действующий прямой поезд или авиарейс.

`calculate_scenario(kind=network)` добавляет или удаляет связи для 1–6 регионов за вызов.
Совместное удаление и добавление одной пары меняет её время. Удаление всех авиасвязей
с выбранным городом моделирует закрытие аэропорта в границах снимка. Поддерживаются
совместные изменения дорог и линий. Направленные рейсы и редактирование частоты пока
не подключены.

Параметр `appraisal` добавляет экономическую оценку для одного региона с его потоками,
ставками и затратами. Время пассажиров берётся из изменённого мультимодального графа.
Грузовой автомобильный маршрут не оценивает перевозку груза поездом или самолётом.
Задания читаются через `manage_calculation(kind=status)`; ранее сохранённые расчёты остаются доступны.


## Дорога между двумя населёнными пунктами

`find_transport(kind=road)` ищет самый быстрый по модельному времени дорожный путь между
двумя населёнными пунктами. Номер трассы не требуется. Поиск идёт с двух сторон
по полному базовому дорожному графу и проходит через участки с разными номерами
или без номера. ЖД и авиация в этот поиск не входят.

Две очереди Дейкстры продолжают поиск, пока сумма их минимальных расстояний не
достигнет лучшего найденного пути. Первое пересечение фронтов само по себе не
доказывает кратчайший путь. Виртуальные соединения между близкими дорогами не создаются.
Конечные пункты используют существующие привязки расчётного снимка. Неоднозначное
название или отсутствие связного пути возвращаются с пояснением.

Инструмент возвращает идентификатор коридора, число OSM ways, модельное время,
расстояния привязки и регионы. `calculate_scenario(kind=close_selection)` может закрыть выбранные объекты
этого маршрута. Сумма длин целых ways может превышать длину поездки; закрытие также
может затронуть их части вне пути. Альтернативные дороги между городами остаются
открытыми. Если пользователь назвал конкретную трассу, маршрут по другим дорогам
нужно обозначить отдельно от этой трассы.


## Единые интерфейсы инструментов

| Инструмент | Запрос |
| --- | --- |
| `query_atlas` | Регионы, поиск мест, населённые пункты, каталог связей, источники и возможности расчёта |
| `find_transport` | Дорога между пунктами с необязательным номером трассы, мосты, ЖД/авиа, узлы и видимая часть графа |
| `calculate_scenario` | Развитие дорог, каталожные транспортные связи, последствия закрытий и критичность |
| `manage_calculation` | Результат, список сохранённых сценариев, отмена и продолжение проверки критичности |
| `present_atlas` | График из рассчитанной таблицы или команда камеры |
| `load_skill` | Предметные инструкции и подключение нужных инструментов |

Каждый запрос имеет `kind` и поля выбранного варианта. Например, дорога между
городами и именованная трасса используют `find_transport` с `kind=road`.
Без `road_name` выполняется встречный поиск по графу, с ним поиск ограничивается
названной трассой. Эти способы не требуют отдельных инструментов модели.

Вызов `calculate_scenario` с `kind=network` принимает `links` для каталожных
транспортных сообщений. Изменения ЖД, авиации и сезонных связей используют общий
расчётный исполнитель. Предметные поля проверяются до выполнения; неизвестная
частота рейса не отбрасывается молча, такой запрос отклоняется.

Старые названия операций остаются внутренними методами, но не регистрируются как
инструменты модели. Сохранённые сообщения и расчёты по-прежнему читаются.

## Окно чата на карте

Чат открывается поверх карты. Перетащите шапку, чтобы переместить окно,
или нижний левый угол, чтобы изменить его размер. Кнопка в шапке разворачивает
окно и возвращает прежние размеры. Крестик закрывает окно, круглая кнопка
чата справа внизу открывает его снова. Закрытие не прерывает ответ и сохраняет
переписку, черновик, выбранную вкладку, положение и размер до ухода со страницы.

Шапка и угол доступны с клавиатуры: стрелки перемещают их на 10 пикселей,
Shift со стрелкой на 40. Окно остаётся внутри карты при изменении размеров браузера.

## Индекс между выбранными населёнными пунктами

Для диагностики backend пишет в журнал Uvicorn события `chat_request_started`,
`chat_tool_started`, `chat_tool_finished`, `chat_request_failed` и
`chat_request_finished`. Общий `request_id` связывает запрос, вызовы навыков и
инструментов, их аргументы и результаты, длительность и итоговый статус.
`tool_call_id` связывает начало и результат отдельного вызова. При ошибке сохраняются
этап, тип, текст, цепочка причин и позиции в стеке без локальных переменных.
Поля с ключами, токенами, паролями и заголовками авторизации скрываются;
текстовые аргументы и результаты ограничены 4000 символами. Полный ответ модели
и история переписки не записываются. Отсутствие `chat_tool_started` при завершённом
запросе позволяет отличить ответ без инструментов от неудачного расчёта.

Навык `settlement-connectivity` подключает расчёт через существующий
`calculate_scenario` с `kind=connectivity`. В `places` передаются от 2 до 12 названий
населённых пунктов, при необходимости с регионом. `mode=all_pairs` сравнивает все пары.
Для поездок к центру задаются `mode=to_center` и `center`, совпадающий с одним из
названий в `places`. Неоднозначные названия и повтор одного пункта отклоняются.

Для оценки закрытия агент сначала находит дороги или мосты через `find_transport`,
затем передаёт все их `selection_ids` в один расчёт связанности. Пустой список
означает исходную сеть. Результат содержит балл группы, время и балл каждой пары
до и после, число потерянных связей и версию графа. Две таблицы появляются прямо
в чате и сохраняются в его истории. Расчёт выполняется без изменения исходных дорог.

Примеры запросов:

- «Оцени связанность Ставрополя, Александровского, Светлограда и Благодарного между собой».
- «Сравни доступность Ставрополя из Александровского, Светлограда и Благодарного».
- «Как изменится связанность этих четырёх пунктов, если закрыть дорогу Ставрополь — Александровское?».

[Методика и границы применения](indices.md#связанность-выбранных-населённых-пунктов).
Числовая проверка инструмента и вывода таблиц выполнялась без платного запроса
к языковой модели. Выбор навыка по свободному тексту отдельным живым запросом не проверен.

Расчёты между выбранными населёнными пунктами имеют постоянный `calculation_id`,
который передаётся в следующий ход через историю таблиц. Агент читает сохранённый
результат через `manage_calculation`, сохраняя исходные значения и границы расчёта.
Исторические расчёты с заданными потоками доступны для денежной оценки по их ID;
[формулы и ограничения](traffic-diversion.md). Поиск разгрузки использует цель
`congestion` единого инструмента развития сети.

`calculate_scenario(kind=connectivity)` и чтение его `status` возвращают компактное
представление: значения, допущения, версии и ID сохранены; списки OSM ways заменены
количествами, повторяющиеся допущения вынесены на уровень результата. Для проверки
конкретных дорог доступен `manage_calculation(kind=status, calculation_id=...,
detail=full)`, который возвращает исходный сохранённый снимок. Таблицы интерфейса
и денежный расчёт используют прежние данные.

Для вопроса «что изменится в регионе» агент вызывает существующий
`inspect_road_stress_test` с названием или ID этого региона. Помимо сводки он
получает охват задержек по порогам, потерянные близкие связи, сопоставимые времена
до/после и названные направления. Правила ответа находятся в `road-scenarios`:
последствие, сравнение, примеры и существенный предел модели. Определение индекса
не подменяет ответ о последствиях. Маленькую таблицу до/после можно составить
в Markdown непосредственно из возвращённых значений.

## Фоновый расчёт в сообщении

Карта выбранного участка показана один раз в начале ответа. Далее идут текст и одна тонкая
полоса прогресса для всех расчётов этого ответа. Внутренние ID, повторные карты и длинные
перечни OSM-названий остаются в данных артефакта и не перегружают сообщение.

После завершения расчётов чат автоматически запрашивает интерпретацию. Сервер читает
сохранённые результаты, а модель формулирует короткий ответ с обычным форматированием:
абзацами, списком и выделением главных выводов. В этом вызове инструменты расчёта отключены.
Ошибки отдельных заданий обозначаются явно; при отсутствии успешных результатов модель
не вызывается. Готовый текст сохраняется в истории и не запрашивается заново при перезагрузке.
При обрыве генерации доступны сохранённый фрагмент и повтор по кнопке.

Сами расчёты продолжаются на сервере. Если ожидающий чат закрыт, проверка результата
возобновляется при его открытии. Уже начатая интерпретация продолжает сохраняться, пока
приложение открыто. Повторный просмотр старых завершённых сообщений не запускает новые
интерпретации всей истории.

Если в истории остался только старый региональный расчёт, агент может вызвать
`stress_test_roads` с `source_calculation_id` и пустыми списками ways/selections.
Сервер переносит точный набор закрытых дорог из сохранённой работы. Поддерживается
чистое перекрытие в режиме `road` на текущей версии графа; смешанные изменения
скоростей, новых дорог и сервисов отклоняются. Совпадающий готовый стресс-тест
возвращается повторно, а новая работа остаётся явно ожидающей завершения.

Автоматическое объяснение завершённого расчёта Hansen также подхватывает уже
готовые дорожные последствия для его региона, если совпадают все закрытые roads,
версия графа и завершённый статус стресс-теста. Оно только читает результаты;
новый расчёт в этом фоновом объяснении не запускается.



## Совместная оценка перекрытия

Обычный `calculate_scenario(kind=close_selection)` запускает вместе региональный
Хансен для регионов выбранных коридоров и национальные дорожные последствия.
`region_ids` расширяет набор регионов для индекса. Выполнение остаётся фоновым;
одна интерпретация получает обе части после завершения. Готовые индексы с теми же
дорогами, версией графа и режимом сети используются повторно.

Чтение перекрытия возвращает индексы до/после, обзор затронутых регионов, примеры
изменившихся направлений и подходящие сохранённые расчёты нагрузки. Их связывает
точное совпадение закрытых дорог и версии графа. Хансен использует активную сеть
атласа и её нормировку; дорожные последствия относятся к отдельной дорожной сети.
Наличие индекса для одного региона не означает расчёт индексов всей страны.

Совпадающие сохранённые расчёты нагрузки могут дополнять чтение последствий.
Отсутствие такого результата не означает отсутствия пробок. Старое перекрытие
можно дополнить индексами через
`stress_test_roads(source_stress_id=..., region_ids=[...], way_ids=[], selection_ids=[])`.

Агент получает подробные факты, но сам выбирает наиболее существенные выводы для
бизнеса и краткую форму ответа. Фиксированного сценария текста нет. Предложения
новых дорог остаются кандидатами для проверки до расчёта их эффекта.

## Таблицы сравнений

`manage_calculation(kind=table)` строит таблицы по сохранённым `scenario_ids` и
`stress_ids`. `view=indices` показывает индекс до, после и изменение; `view=routes`
разделяет отправление, назначение и время до/после; `view=access` показывает потери
ближних связей и охват задержек. Модель выбирает вид и регионы, но не заполняет ячейки.
Сценарии разделены и подписаны названиями дорог из расчётного графа.

Автоматическое объяснение получает готовые таблицы индекса и пишет только выводы.
Таблицы сохраняются вместе с ответом. Старые сохранённые объяснения с Markdown-таблицами
заменяются на экране таблицами из результатов через `POST /api/v1/chat/calculation-tables`,
без обращения к языковой модели. Исходная история остаётся в хранилище браузера.

## Название и чтение диалога

Для первого вопроса нового диалога агент создаёт короткое название через `name_chat`.
Оно сохраняется в браузере вместе с сообщениями. Последующие вопросы и автоматические
интерпретации расчётов название не меняют. Пока название не получено, в списке виден
первый вопрос; старые диалоги сохраняют эту подпись.

При прокрутке вверх чат перестаёт следовать за новым текстом и растущими карточками.
Автопрокрутка возобновляется, когда читатель возвращается к нижнему краю или отправляет
новый вопрос. Появление сообщений меняет прозрачность без сдвига текста.

### История дорожных экспериментов

Сохранённые результаты прежнего поиска доступны через `manage_calculation` с
`calculation_type=traffic`. Повторный запуск поиска удалён. Просмотр истории
не требует обученной модели. Перекрытия существующих коридоров остаются доступны
через `calculate_scenario(kind=close_selection)`.
