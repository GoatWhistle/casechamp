# Потенциальная доступность при планировании поездки

> Версия `hansen-planned-v1` оценивает поездку, заранее подстроенную под отправление.
> Неизвестная частота остаётся неизвестной. Результат по точному расписанию отсутствует.

**Читайте, если** сравниваете вклад авиации, ЖД и водных связей · **Связано:** [Индекс Hansen](indices.md) · [Ограничения](limitations.md)

---

## Что показывает сравнение?

Карточка на странице региона содержит летний и зимний результаты: прежний метод,
потенциальную доступность и разницу в пунктах индекса. Оба результата используют
один исходный снимок, население рынков и населённых пунктов и одну нормировку.
Рейтинг карты и дорожные сценарии сохраняют опубликованный метод.

В сохранённом снимке `hansen-release-20261107` магистральные ЖД и авиация уже
учитывались без отдельного ожидания отправления. Поэтому новая оценка не является
«возвращением авиации в индекс». Она убирает ожидание местных линий, задаёт единое
правило посадки на паром и сохраняет конечные пути длиннее 72 часов.

Национальная версия `hansen-frequency-v2` использует другое правило: при неизвестной
частоте магистральной линии ожидается один рейс в неделю. Эта версия не подменяет
сохранённый снимок в сравнении.

## Какие затраты остаются?

| Связь | Затраты потенциальной поездки |
| --- | --- |
| Магистральная авиация | Время перелёта из источника и 2,5 часа накладных расходов |
| Магистральная ЖД | Время поездки из источника и 1 час накладных расходов |
| Местная линия | `travel_h` из расчётного источника, включая его накладные расходы |
| Паром OSM | Время движения по графу и 0,5 часа при входе на паромный way |
| Ручная паромная переправа | Подъезд, пересечение и 0,5 часа, уже включённые в `travel_h` |

Ожидание даты отправления не включается. Это оптимистическое допущение планирования,
а не утверждение о немедленной доступности рейса. Правило 0,5 часа для парома является
модельным параметром. При разделении одной физической линии на несколько OSM way
оно может начисляться повторно; без идентификатора линии эти записи не объединяются.

Для парома OSM используются отдельные узлы посадки: плата временем возникает при входе,
а движение по нескольким сегментам одного way её не повторяет. Направления дорог
симметризуются, направления магистральных пар сохраняются. Местные связи двусторонние,
как в исходном снимке. Сезонные ограничения старого дорожного графа не восстанавливаются
по предположению; лето и зима различаются местными связями источника.

## Как связаны версии и шкала?

Формула остаётся `A_i(h) = Σ_j M_j × exp(−ln(2) × t_ij / h)`.
Региональное значение взвешено по населению исходных пунктов. Для вариантов 2, 4 и
8 часов используется одна сохранённая нормировка `B`: `H = 100 × A / B`.

В снимке `data-20261107` базовый вариант включает магистральные ЖД и авиацию.
Его среднее 100 нельзя называть средним по чисто дорожной сети. Варианты 4 и 8 часов
проверяют чувствительность и не откалиброваны по поведению жителей. Они не получают
собственную нормировку 100. Прежний метод при каждом полупериоде пересчитывается
из сохранённых времён, а не умножением опубликованного индекса на коэффициент.

Новая оценка может быть ниже прежней: ожидание местных отправлений убрано,
но у паромов OSM добавлено время посадки. Разница методов включает оба изменения.

## Как измеряется вклад транспорта?

Из полной потенциальной сети поочерёдно исключаются авиация, ЖД и водные связи
(паромы вместе с реками). После каждого исключения ищутся новые кратчайшие пути.
Вклад равен `H_полная − H_без_вида` в пунктах индекса. Полная сеть и каждый вариант
имеют одинаковые исходные пункты, веса и нормировку. Эти вклады не складываются:
маршруты могут заменять или дополнять друг друга.

## Что означает полнота расписаний?

Счётчики показывают число исходных записей с положительной, не подставленной
частотой. Они относятся к национальному набору связей. Паромные way OSM считаются
записями без известной частоты. Это не число рейсов и не доля населения с подтверждённым
расписанием. Известная частота сама по себе не подтверждает актуальность сообщения.
Магистральные пары из матрицы являются модельными: они не подтверждают прямой
рейс или поезд. Новые расписания, видимые на карте, в сохранённый расчётный снимок не входят.

`scheduled_index = null` означает отсутствие расчёта по точному расписанию. Ноль
вместо отсутствующих данных не возвращается. Функция расчёта затрат хранит неизвестную
частоту как `None`; для известной частоты отдельно допускается оценка ожидания `84/f`.
Такая оценка предполагает равные интервалы и случайный момент потребности; она не
выдаётся за маршрутизацию по календарю отправлений.

## Как воспроизвести расчёт?

```bash
set -a
source .env.analytics
set +a
PYTHONPATH=backend/src:etl OPENBLAS_NUM_THREADS=1 \
  .venv/bin/python -m accessibility.calculate --workers 2
```

По умолчанию команда закрепляет активный снимок `hansen-release-20261107` и явно
отказывается рассчитывать другую модель. Для сохранённого снимка используется
`--source-revision d974f339a31d03fd`, даже если рабочий граф уже обновился. Исходные таблицы закрепляются в отдельной
базе ClickHouse через `ATTACH PARTITION ALL FROM`; рабочие таблицы не изменяются.
Схема результатов находится в `etl/accessibility/schema.sql`.

`plexus_accessibility.results` хранит значения, `frequencies` содержит счётчики,
`runs` фиксирует только завершённые вычисления. Незавершённый запуск не виден API.
Частичные вычисления сохраняются в `data/accessibility-cache` для повторного запуска.
Если рабочий граф сменился, API возвращает `source_current=false`, а карточка
обозначает результат как сравнение на сохранённом снимке.
