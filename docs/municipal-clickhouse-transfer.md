# Перенос муниципальных расчётов

Исходники и JSON-кэши не заменяют рабочие таблицы ClickHouse. Для нормативов
нужны сохранённые измерения и пешие сети, для нового расчёта нагрузки — жилые
точки, для дорожных сценариев — исходные параметры дорог.

Опубликовано дополнение к снимку `data-clickhouse-20261110`: 55 таблиц,
2 697 797 670 байт. Размеры и SHA-256 всех таблиц и манифеста на GitHub
совпадают с локальными файлами. Релиз —
[data-municipal-20261113](https://github.com/GoatWhistle/casechamp/releases/tag/data-municipal-20261113).
Файлы `*.native.gz` и `manifest.json` содержат базы `plexus_normative`,
`plexus_synthetic_traffic`, `plexus_graph` и `plexus_atlas.atlas_metadata`.
Архив `plexus-national-snapshot-v2.tar.gz` в том же релизе содержит отдельный
численный граф; это другой формат, он не заменяет таблицы БД.

Из корня актуального `main`:

```sh
gh release download data-municipal-20261113 -R GoatWhistle/casechamp \
  -p '*.native.gz' -p manifest.json -D data/releases/data-municipal-clickhouse-20261113
set -a
source .env.analytics
set +a
backend/.venv/bin/python etl/analytics/restore_snapshot.py \
  data/releases/data-municipal-clickhouse-20261113 \
  --database-prefix plexus_transfer_
```

Восстановление сначала проверяет SHA-256 всех выбранных файлов, затем создаёт
таблицы и проверяет число строк. Префикс создаёт отдельные базы для проверки,
не меняя работающий стенд. Зависимость `housing_current` переносится вместе с
префиксом. Существующие таблицы скрипт не перезаписывает.

В новой пустой базе можно убрать `--database-prefix`. На действующем сервере
заменять таблицы следует только после проверки снимка, остановки API и расчётных
воркеров и сохранения старого набора. Смена префикса сама по себе не подключает
новые таблицы к API. После переключения таблиц перезапустите API: в процессе
кэшируются справочники и версия источника.

Данные `plexus_scenario` сюда не входят: локальной матрицы старой лаборатории
нет. Этот снимок не устраняет её HTTP 503. Предварительные нагрузки остаются
синтетическими; наличие жилых точек позволяет запускать расчёты, но не означает,
что все сценарии уже рассчитаны или совпадут с наблюдаемым движением.

Экспорт читает таблицы независимо, общей транзакции снимка нет. Для каждой
таблицы проверяются число строк и DDL до и после чтения. Экспортёр сохраняет
резерв диска: по умолчанию 15 ГиБ, параметр `--min-free-gib` задаёт другой резерв
не меньше 1 ГиБ. Для этой выгрузки выбран резерв 5 ГиБ; проверка выполняется
при каждом блоке чтения, неполный файл не включается в манифест.

Проверка 13.11.2026: в отдельные базы восстановлены `road_costs` (4 301 210
строк), `criteria` (9), `housing` (7 077 955) и `housing_current` (6 404 792).
Для первых двух таблиц совпали контрольные отпечатки содержимого; для всех
четырёх — число строк. Представление жилья читает новую базу. Полное
восстановление всех 55 таблиц и проверка API на другом сервере не выполнялись.
