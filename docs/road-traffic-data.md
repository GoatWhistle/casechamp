# Полосность и наблюдения дорожного движения

Данные предназначены для проверки исходных характеристик дорог и доступности измерений
трафика по 82 регионам атласа. Они хранятся отдельно от весов расчётного графа.
Действующий индекс Hansen, модельные скорости и результаты сценариев этот сбор не меняет.

## Дорожные характеристики

Источник — сохранённый снимок Geofabrik от 09.11.2026, таблица
`plexus_refresh_graph.ways`. Исходные OSM-теги сохраняются вместе с численными полями.
Полосность относится к OSM way, а не обязательно к целой дороге. Статус `valid` означает
успешный разбор и согласованность тегов; натурная проверка числа полос не выполнялась.

`lanes` означает общее число полос; `lanes:forward` и `lanes:backward` задаются относительно
направления исходного way. Обратная односторонняя дорога сохраняется отдельно. Общая полоса
`lanes:both_ways` не становится дополнительной полосой каждого направления. Если разбивка
по направлениям отсутствует, она остаётся неизвестной. Автобусные и поворотные полосы
сохраняются в исходных тегах; автоматической оценки автомобильной пропускной способности нет.
Правила: [OSM lanes](https://wiki.openstreetmap.org/wiki/Key:lanes),
[oneway](https://wiki.openstreetmap.org/wiki/Key:oneway).

Ограничение `maxspeed` является разрешённой скоростью, не наблюдаемой скоростью потока.
Значения в mph переводятся в км/ч; условные, составные и символические ограничения
сохраняются с признаком неоднозначности. [OSM maxspeed](https://wiki.openstreetmap.org/wiki/Key:maxspeed).

В отчёте отдельно показаны все дорожные классы и основные классы motorway–tertiary
с их съездами. Длины рассчитываются по геометрии расчётного снимка, пересечённой с
границами атласа, на эллипсоиде WGS84. Обратные рёбра не удваивают длину; раздельные
проезжие части считаются отдельно. Общая граница регионов принадлежит региону с меньшим
идентификатором. Это покрытие данных OSM, а не проверка полноты реальной дорожной сети.

## Измерения

Региональные официальные органы сопоставлены по
[каталогу Минтранса](https://www.mintrans.gov.ru/activities). Журнал поиска различает
полученную страницу, найденную ссылку, сохранённый документ и численно разобранные измерения.
Ошибка доступа не означает отсутствие данных в регионе.

В набор входят исторические обследования Серова, Нефтеюганска и Беловского района.
Новые строки XLSX [Куздора](https://kuzdor.ru/nasha-deyatelnost/soderzhanie-avtomobilnyh-dorog/otchet-ob-intensivnosti/)
с текстовым километражем сохраняются: всего 57 строк постов/перегонов. Заголовок книги
содержит «за 2023 год» и «по состоянию на 01.01.2026»; год наблюдений не установлен.

Запись набора может быть отдельным классом транспорта, пустой ячейкой или экстремальным
показателем. Число записей не равно числу постов, поездок или независимых измерений.
Исходные расчётные скорости, плотности и пропускные способности отчётов отмечены как
расчётные параметры. Несогласованные суммы классов и опубликованные итоги не исправляются.

Суточные и часовые значения, фактические автомобили и приведённые единицы не объединяются.
Неизвестная продолжительность обследования и пустая ячейка остаются неизвестными.
Суточный поток не переводится в пиковый час без распределения по времени и направлениям.
[Объяснение FHWA](https://www.fhwa.dot.gov/policyinformation/pubs/traffic-data-applications-highlights/traffic-data-for-highway-engineering.cfm).

Привязка по названию или близости геометрии имеет статус кандидата. Для подтверждения
нужны ID наблюдения, OSM way, версия графа и ссылка на проверенное положение поста/сечения.
Подтверждения находятся в `datasets/additional/road-traffic/confirmations.json`.
Один пост не задаёт поток всей трассы. Поиск кандидатов ограничен 500 геометриями на запрос;
кандидаты требуют проверки и не доказывают полноту геопривязки.

## Запуск и хранение

Из корня проекта:

```bash
uv sync --group traffic
set -a
source .env.analytics
set +a
PYTHONPATH=etl .venv/bin/python -m road_traffic run
```

Для изолированной проверки можно задать другой `CLICKHOUSE_URL` и `--database`.
Для извлечения таблиц PDF нужен `pdftotext` из Poppler и сохранённые исторические CSV
обследований в `data/additional/traffic-surveys`. Отсутствующий источник вызывает явную
ошибку с его путём. Требуются четыре исходные таблицы: `plexus_refresh_graph.ways`, `road_lines`,
`plexus_atlas.atlas_regions` и `atlas_boundaries`.

`plexus_traffic` содержит запуски, источники, атрибуты, исходные наблюдения, соответствия
графу, промежуточные региональные фрагменты и сводку покрытия. Каждый запуск закрепляет
дорожные таблицы в `plexus_traffic_snapshot_<run_id>` через копирование разделов.
Атрибуты и география обрабатываются порциями. При повторе незавершённого этапа очищаются
только его строки этого запуска; другие запуски сохраняются. Указанный вручную `--run-id`
нужно повторять только для тех же исходных данных и той же версии обработки.

`--only attributes`, `--only coverage` и `--only observations` позволяют выполнить этап.
Покрытие требует готовых атрибутов; сопоставление наблюдений требует готового покрытия.
Частичный запуск не имеет статуса `completed`. Полный запуск проверяет обратное чтение
82 строк региональной сводки из ClickHouse и сохраняет CSV/JSON в
`data/additional/road-traffic/results`. Верифицированные результаты и ограничения запуска
публикуются отдельно от исходников, содержащих пользовательские пути и журналы поиска.


Сведения о проверке источников и новые измерения Обнинска/Биробиджана:
[каталог](../datasets/additional/road-traffic/README.md),
[новые обследования](../datasets/additional/road-traffic/new-surveys.md).

## Проверенный срез 11.11.2026

Запуск `roadtraffic20261111v1` завершён и перенесён в `plexus_traffic` основной БД.
Для шести таблиц проверены количество строк, сумма cityHash64 и XOR sipHash64.
Исходные графы перед переносом сопоставлены отдельно. Метод, версия и контрольные
значения доступны в [протоколе](results/road-traffic-validation.json),
покрытие каждого региона — в [CSV](results/road-traffic-coverage.csv) и
[JSON](results/road-traffic-coverage.json).

Обработаны 6 869 793 OSM way и 6 881 214 дорожных геометрий без паромов.
Корректно разобранные теги полосности покрывают 32,3% длины геометрий основных
классов и 6,4% всех дорожных классов в границах 82 регионов. Геометрия упрощена
до узлов расчётного графа, поэтому её длина может быть меньше длины исходной
полилинии. Эти доли относятся к сохранённому снимку.

Сохранены восемь документов и 6846 записей источников: 2337 числовых значений,
4509 пропусков. Числовые значения относятся к пяти регионам. В поле `sites`
считаются различные подписи мест наблюдения, а не физические посты: у разных
постов может быть одинаковое название улицы.

Для 743 записей найдены кандидаты геопривязки, 6103 остаются несопоставленными.
Подтверждённых привязок нет. Ни одно число потока не назначено ребру расчётного
графа; узловые суммы Обнинска не распределены по примыкающим дорогам. Для модели
задержек ещё нужны проверка привязок, направлений и сопоставимых периодов.

## Допущение для неизвестной полосности

По выбранному пользователем правилу `narrow_unknown_lanes_v1` дорога без данных
о полосности считается узкой: одна полоса в каждом направлении, две всего.
Для односторонней дороги принимается одна полоса в разрешённом направлении.
Если односторонность не указана, двусторонность также отмечается как допущение.

В `plexus_traffic.road_attributes_effective` исходные поля сохранены рядом с
`effective_lanes_total`, `effective_lanes_forward` и `effective_lanes_backward`.
`lanes_assumed=1` и `lanes_basis=narrow_unknown_lanes_v1` отличают допущение от
данных OSM. Исходный `lanes_status` остаётся `missing`. Известные значения
не заменяются; противоречия, неразобранные теги, паромы и дороги с переменным
направлением требуют отдельной проверки. Условная полосность не заменяется
постоянным значением.

Правило применяется к 6 384 248 объектам текущего снимка. Контрольные количества
и значения по направлениям: [проверка](results/road-narrow-lanes-validation.json).
Доли наблюдаемого покрытия в прежнем отчёте сохраняются. Подстановка полосности
не заполняет неизвестную интенсивность. В [модели дорожной стоимости](road-capacity.md)
полосность определяет пропускную способность, задержка применяется только при
подтверждённом часовом потоке. В текущем расчёте таких привязок нет, поэтому
дороги используют свободное движение и одни дополнительные полосы не меняют Hansen.
