# Поиск изменений дорожной сети

> Основной поиск сравнивает изменения существующих дорог, новые коридоры и совместные пакеты. Кандидаты получают очередь через обязательный CatBoost; итоговый эффект подтверждается расчётом потоков и индекса.

**Читайте, если** запускаете поиск или проверяете его ограничения. **Связано:** [Сценарный спрос](synthetic-traffic.md).

## Сколько времени получают генерация и проверка?

На генерацию вариантов по умолчанию отводится 120 секунд. После неё начинается отдельное окно точной проверки длительностью 300 секунд. Неиспользованное время генерации не сокращает время проверки. Генерация строит варианты коридоров; точная проверка пересчитывает эффект кандидатов на выбранную цель.

Подготовка снимка, исходного спроса, распределения потоков и деревьев путей выполняется до обоих окон. Подготовка запроса агентом также не входит в эти сроки. Полное время ответа включает подготовку и накладные расходы запуска и завершения процессов сверх этих окон. Проверка срока кооперативная. После завершения проверки дальнейшего улучшения результата в фоне нет.

`TRAFFIC_WORKERS` задаёт число процессов, не больше 32 и числа доступных CPU. Пакеты состоят из двух совместимых проектов. Поиск не доказывает глобальный оптимум и не перебирает все возможные комбинации. Денежный бюджет не применяется.

## Что пересчитывается через diff?

Исходные деревья кратчайших путей и распределения спроса сохраняются. Закрытие или увеличение времени инвалидирует затронутые поддеревья; новая связь и уменьшение времени запускают распространение улучшений. Потоки обновляются для изменившихся деревьев. Изменение задержек снова запускает ремонт путей до сходимости либо лимита итераций.

Региональный индекс использует общие рынки, население, привязки и нормировку атласа. Деревья рынков хранятся в дисковых массивах по отпечатку графа. Для 180 рынков и 6 990 556 узлов исходные расстояния и родители требуют около 15,1 ГБ диска; свободное место проверяется перед построением. Кандидат сохраняет только изменённые узлы, временные файлы удаляются после оценки. Ремонт деревьев компилируется Numba до запуска таймера; для действующей методики сохраняется её горизонт 72 часа. Его деревья также обновляются через diff. Сборка графа и агрегация индекса просматривают массивы; это не полностью локальная стоимость вычислений. Для кандидата список изменённых направленных рёбер формируется при наложении изменений на граф. Неизменённые деревья рынков пропускаются; до четырёх затронутых деревьев ремонтируются параллельно. Агрегация читает только изменения расстояний для населённых пунктов и рынков. Если изменились межрыночные пути, индекс пересчитывается для всех выбранных населённых пунктов; иначе — только для затронутых. Область влияния может охватить всю сеть. Направления потоков сохраняются, индекс использует существующую ненаправленную методику атласа.

## Как получаются новые трассы?

A* проходит по подготовленной сетке местности с восемью соседями. Здания и охраняемые территории блокируют ячейки, вода требует мостового варианта, крутой рельеф рассматривается с тоннелем. Альтернативные проходы получают штраф за совпадение с найденной трассой. В расчёт и на карту передаётся одна полилиния и её измеренная длина. Ломаная сетки упрощается только там, где весь пересекаемый растр свободен; оставшиеся повороты заменяются проверенными по растру круговыми дугами. Скорость задаётся отдельно для участков с учётом предлагаемого радиуса, уклона и сооружений. Время равно сумме времён участков, а эквивалентная скорость — длине, делённой на это время. Один медленный поворот не ограничивает всю трассу. Для текущего класса двухполосного соединения принято 60 км/ч до локальных ограничений; это параметр сценария, а не измеренная скорость или норматив категории дороги.

Для дуг используется связь радиуса, поперечного уклона и бокового трения: `V² = 127R(e+f)`. В сценарии приняты `e=0,04` и `f=0,15`; эти допущения не подтверждают нормативное соответствие проекта. [Физическая модель FHWA](https://highways.dot.gov/safety/speed-management/speed-concepts-informational-guide/chapter-4-engineering-and-technical), [формула в метрических единицах](https://www.mdt.mt.gov/other/webdata/external/traffic/manual/chapter_25.pdf).

Это предварительный отбор по растру. Подробная геометрия развязок, радиусы кривых, геология, порталы и строительная пригодность сооружений не подтверждаются. Растр может пропускать объекты меньше ячейки. Самостоятельного повышения скорости нет. Добавление полос допускается после предварительной проверки расширяемого коридора по географическому растру; без покрытия или при препятствиях кандидат исключается. Эти пределы не являются инженерным согласованием.

Без слоёв высот, зданий, воды и охраняемых зон новые коридоры и расширения не генерируются. Проверки закрытий остаются доступны. Открытие требует исходной геометрии и ссылки на существующий проезд. Произвольного открытия дороги по прямой нет.

Подготовка реальных входов:

```bash
cd backend
uv run python -m synthetic_traffic.geography_fetch --help
uv run python -m synthetic_traffic.geography_prepare --help
```

`TRAFFIC_GEOGRAPHY` указывает подготовленный JSON, NPZ или каталог тайлов. Без переменной используется каталог `traffic-geography-national`, если в нём есть готовые тайлы, иначе `traffic-geography/geography.json` рядом с каталогом `GRAPH_DIR`. Каталог загружается только в выбранном окне; непокрытые ячейки блокируются. Покрытие ограничено границами растра. Copernicus GLO-30 содержит высоту поверхности, включая растительность и постройки, а не чистый рельеф. Источники и SHA-256 сохраняются при загрузке. [Copernicus GLO-30](https://copernicus-dem-30m.s3.amazonaws.com/readme.html), [OSM Overpass](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL).

## Что делает CatBoost?

Файл `etl/synthetic_traffic/surrogate.cbm` обязателен. Учебные вмешательства не содержат самостоятельного повышения скорости. При отсутствии или несовместимой схеме поиск сообщает ошибку. Модель задаёт порядок вычислений; её прогноз не публикуется как подтверждённый эффект. Учебные метки получены полным распределением потоков; несошедшиеся решения исключены.

Протокол, размер выборок, seed и ошибки находятся в [surrogate.json](../etl/synthetic_traffic/surrogate.json). Корпус включает небольшие синтетические сети и два локальных дорожных снимка с синтетическим спросом. Это проверка вычислительного отбора, не точности реального трафика. Метка обучения описывает локальную доступность, финальная сортировка приложения использует региональный индекс. В схеме v2 учебные примеры включают новые связи и смешанные пакеты. Географически пересекающиеся дорожные снимки не дают независимой проверки переноса на другой регион.

```bash
cd backend
uv run python -m synthetic_traffic.training --help
```

## Как выбирается цель?

Агент использует один `calculate_scenario(kind=traffic_development)`. `objective=connectivity` повышает индекс связанности, `transit` уменьшает среднее время фиксированного набора исходных транзитных поездок через выбранную область, `congestion` уменьшает суммарные задержки на её дорогах. Потеря доступных поездок не считается улучшением. Транзит не выдумывается при отсутствии соответствующих пар спроса.

Агент может передать в том же запросе `hypotheses`: список пар `source_place`, `target_place` с кратким `rationale`. Это направления, которые стоит проверить, а не готовые трассы. Названия разрешаются по сохранённым населённым пунктам, затем используются реальные привязки к дорожному графу. Агент не задаёт геометрию, произвольное время новой дороги или самостоятельное повышение скорости. Для принятой пары коридор строится по географическому растру. Если сглаживание не проходит проверку, поиск увеличивает штраф возле проблемного участка и повторяет построение: не более трёх попыток на пару в общем окне генерации. Ограничения по воде, зданиям, охраняемым зонам и уклону сохраняются. Полученные варианты поступают в общую очередь точной проверки; до окончания окна могут быть проверены не все. Если привязка населённого пункта попала в заблокированную ячейку, поиск выбирает доступный узел в пределах 2 км по существующей дороге. Исходные узлы, пройденное расстояние и причина гипотезы сохраняются. Недоступные пары пропускаются с объяснением. До четверти мест в очереди построения коридоров резервируется для гипотез; итоговый эффект оценивается общей формулой. Совпадения с автоматическими парами сохраняют оба источника.

Один город задаётся через `places`. Без `focus_bounds` область измерения строится по закреплённым за поселением жилым зданиям с отступом 100 м. Это граница жилой застройки, не административная граница. Явная область карты имеет приоритет. При нехватке исходных домов расчёт просит область, а не придумывает координаты.

На точную проверку индекса одного кандидата отводится до 60 секунд в пределах отдельного 300-секундного окна проверки. Незавершённая проверка отбрасывается; оставшееся время получают другие кандидаты. Поэтому тяжёлый вариант может остаться непроверенным, даже если он потенциально лучше.

## Что получает пользователь?

Лучшие завершённые варианты, их геометрию, изменение индекса и локальные последствия. Рост перегрузки не запрещает рекомендацию: он явно выводится рядом с результатом. Нет результата с неподтверждённой сходимостью. Новая доступная поездка не исключается из полезных вариантов только потому, что среднее время нельзя сравнить с прежним набором доступных поездок.

## Что измерено на пилоте?

Все приведённые ниже измерения относятся к прежнему общему окну поиска до 60 секунд. Они сохранены как исторические результаты и не подтверждают время или эффект текущего режима с отдельными окнами генерации и проверки. Текущий прогон с пределами 120 и 300 секунд приведён отдельно ниже.

12 ноября 2026 года локальный поиск на снимке с 11 312 направленными рёбрами и 110 парами спроса завершился за 54,95 секунды. Он обработал 319 проектов и пакетов; пул содержал 31 коридор. Цель прогона была локальной доступностью, а не национальным индексом. Это исторический прогон до исключения самостоятельных скоростных вмешательств, он не подтверждает текущие прибавки или минутный поиск по всей России. Источники географии относятся к пилотному окну Невинномысска.


12 ноября 2026 года пилот повторён без самостоятельных изменений скорости. На том же дорожном снимке и 110 синтетических парах спроса проверены 194 проекта и пакета за 9,96 секунды. Геопроверка допустила 2 из 64 вариантов добавления полос; дополнительно сформированы 32 новые трассы и 32 закрытия. Скорость новых связей определяется предварительными параметрами класса, покрытия, поворотов, уклонов и сооружений.

Лучший завершённый вариант поднял локальную доступность с 0,7704531624 до 0,7704541416: +0,0001271%. Экономия составила 0,008863 автомобиле-часа за час модели, число перегруженных направленных рёбер осталось 3. Это практически нулевой эффект. Значение относится к локальной доступности, не к опубликованному региональному индексу и не к наблюдаемому дорожному трафику. Протокол сохранён в `work/network-development/pilot-no-speed.json`.

Проверка с опубликованной региональной методикой на национальном графе завершила 34 точные оценки из 39 обработанных кандидатов за 60,23 секунды поиска. Положительных изменений регионального индекса не найдено. Подготовка заняла 44,82 секунды, полный запуск — 105,08 секунды. Минутный ответ целиком не достигнут; существенный эффект новых предложений на региональный индекс этим пилотом не подтверждён.


## Что показал пилот с LLM-гипотезами?

12 ноября 2026 года выполнено одно последовательное сравнение на одинаковых географии, графе и 4 420 парах синтетического спроса: автоматический поиск и тот же поиск с 11 гипотезами gpt-6.1-sol. Проверка индекса заняла 300,18 и 300,20 секунды; полную оценку прошли 5 и 6 проектов соответственно. Подтверждённый прирост индекса равен нулю. В каждом прогоне ещё три проверки прерваны по времени; их эффект неизвестен.

В прогоне с LLM восемь пар прошли первичный отбор доступных узлов, но ни одна соответствующая трасса не прошла построение и проверку геометрии. Поэтому сравнение не устанавливает полезность LLM для индекса. Индекс Ставропольского края для завершённых проверок остался 99,15140597565384. Это отрицательный результат поиска до локального пересчёта и повторной прокладки, без утверждения, что полезных вмешательств не существует. [Протокол и результаты](results/network-hypothesis-pilot.json).


## Что измерено для локального пересчёта индекса?

На одном сохранённом кандидате проверка, ранее прерывавшаяся через 60,08 секунды, завершилась за 50,44 секунды после перехода к чтению только изменённых расстояний. С четырьмя потоками ремонта она заняла 30,13 секунды и дала в точности те же региональные значения. Пиковая память процесса — 3,38 ГБ. Это одиночные замеры с разным состоянием дискового кэша и фоновой нагрузкой, без утверждения об ускорении всех запросов.

Для этого кандидата взвешенный индекс трёх затронутых регионов изменился с 95,116400989 до 95,117098029. Основная прибавка относится к Карачаево-Черкесии; заметного улучшения для Ставрополья нет. Синтетическая нагрузка даёт экономию 1,578 машино-часа в час. Кандидат не относится к LLM-гипотезам. [Измерения и ограничения](results/network-index-local-diff.json).


## Повторный LLM-пилот после исправлений

12 ноября 2026 года повторный поиск с теми же 11 сохранёнными LLM-гипотезами построил 28 допустимых коридоров, включая два из гипотез. Генерация заняла 120,18 секунды, проверка — 300,13 секунды; подготовка выполнялась отдельно. Полную проверку индекса прошли 19 проектов, ещё один не успел завершиться. Обе LLM-трассы дали положительный эффект.

Новая Деревня — Саратовский, 10,45 км: индекс Ставропольского края изменился с 99,1514059757 до 99,1518710917 (+0,0004651161 пункта). Апсуа — Саратовский, 16,13 км: с 99,1514059757 до 99,1515242800 (+0,0001183043 пункта). Скорости следуют параметрам трасс; самостоятельных скоростных вмешательств нет.

Лучший автоматический вариант дал +0,0011267325 пункта взвешенного индекса трёх регионов, преимущественно за счёт Карачаево-Черкесии (+0,0203876164 пункта). Прибавки небольшие. Это расчёт на реальном дорожном графе с синтетическим спросом. Прогон без контрольной ветки не доказывает преимущество LLM над автоматическим поиском. [Результаты и ограничения](results/network-llm-pilot-local-diff.json).

Проверка прежнего суррогата выявила ограничение: девять разных новых трасс получили одинаковый прогноз CatBoost. В схеме v2 добавлены времена поездки между концами в обоих направлениях, недоступность направлений, расчётные потоки и задержки возле концов, время и пропускная способность новой дороги. Модель переобучена: 1 081 учебный и 433 отложенных примера. Среди 186 отложенных примеров новых связей и содержащих их пакетов средняя абсолютная ошибка локальной доступности — 0,00702 против 0,01371 у постоянного нулевого прогноза. Отрицательные результаты ранжирования также сохранены в manifest; это не проверка национального индекса на независимых регионах.

Повторное ранжирование 19 ранее точно проверенных проектов теперь ставит первым вариант с приростом регионального индекса +0,0002539963 вместо нулевого. Лучший известный вариант входит в первую десятку; старый суррогат его туда не включал. Это диагностическое сравнение на ранее отобранном пуле, часть геометрии которого использована для локальных учебных меток. Оно не заменяет полный прогон и независимую проверку.

Завершённые точные оценки сохраняются вместе с проектом и названием метрики, включая отрицательные и нулевые эффекты. Незавершённые проверки не превращаются в нулевые учебные метки. Переобучение выполняется отдельно и не продолжается после ответа пользователю.


## Полный пилот нового отбора
