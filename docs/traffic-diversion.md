# Перекрытие с переносом потока

Режим `calculate_scenario(kind=connectivity, traffic={})` рассчитывает влияние
закрытых дорог на выбранные населённые пункты с учётом модельного транзита.
Он доступен для 2–4 пунктов; обычный расчёт без переноса потока — для 2–12.
Это сценарий с допущениями, а не прогноз по измеренному трафику.

По умолчанию загрузка равна 50% модельной пропускной способности, длительность
перекрытия — один час, пропускная способность — 1800 приведённых авто на полосу
в час. Все три величины можно изменить в `traffic`: `utilization`,
`duration_hours`, `capacity_per_lane_pcu_h`. Загрузка строго между 0 и 1,
длительность — до 24 часов постоянного спроса. Среднесуточная интенсивность
автоматически не подставляется вместо часовой.

## Расчёт

1. На исходном пути выбранной пары находятся закрытые участки. Поток одного
   условного направления равен загрузке, умноженной на минимальную пропускную
   способность закрытого участка. Последовательные рёбра одного моста не
   создают несколько копий потока. Закрытые участки вне этого пути исключены
   из оценки спроса.
2. По исходному пути выбираются ближайшие развилки до и после закрытого
   фрагмента. Между ними ищутся до пяти объездов без общих рёбер. Общие узлы
   допустимы; узловая пропускная способность отдельно не задана.
3. Весь заданный поток распределяется между найденными объездами по равенству
   среднего времени используемых маршрутов. Фоновая загрузка каждого объезда
   сохраняется. Если объездов нет, поток остаётся необслуженным; он не исчезает
   из результата. Назначение на маршрут не означает, что весь поток успел
   пройти его за период перекрытия.
4. Время движения по каждому ребру увеличивается по функции
   `t0 × (1 + 0,15 × min(q/C, 1)^4)`. При превышении способности узкого места
   отдельно считается очередь: `N(T) = max(q − C, 0) × T`, среднее ожидание
   прибывающего за период потока — `N(T)/(2C)`. Здесь `q` включает фон.
   Очередь начинается с нуля. В расчёте ожидания сохраняется обслуживание
   через тот же объезд, включая завершение поездок после периода поступления.
   Произвольного «падения способности на процент» модель не добавляет.
5. Нагрузка назначается рёбрам объездов, ожидание — первому узкому месту
   маршрута. Между населёнными пунктами заново ищется самый быстрый путь
   по этой сети. Местная поездка может обходить мост раньше транзитного потока;
   её время не приравнивается к полному объезду между подходами к мосту.

Полосность берётся из дорожных профилей OSM. При неизвестном количестве полос
используется существующее узкое приближение: одна полоса на направление.
Такие дороги перечисляются в `assumed_lane_ways` и `assumed_source_lane_ways`.
Скорости и покрытия используются из действующей модели стоимости дороги;
подтверждённая задержка исходного профиля снимается с исследуемого маршрута
перед применением сценарной нагрузки, чтобы не складывать два предположения
о потоке на одном ребре.

## Границы результата

Каждая пара — отдельный эксперимент для одного условного направления.
Потоки, очереди и потери разных пар **нельзя суммировать**: транзит может
повторяться. Удаляются все выбранные дорожные участки, но нагрузка оценивается
для закрытого коридора на исходном пути конкретной пары. Это не перенос всего
трафика области или всех направлений федеральной трассы.

Граф остаётся неориентированным. Модель не проверяет законность движения
по односторонним участкам и грузовые ограничения, не моделирует светофоры,
распространение очереди на соседние перекрёстки и изменение спроса. Ограничение
набора объездов исключает часть маршрутов с общими участками и способно завысить
стоимость объезда. Для дороги с одной общей полосой пропускная способность
относится к общему сечению; противоположный поток отдельно не восстанавливается.
Расположение очереди — приближение, которое влияет на время местной поездки.

Населённый пункт по-прежнему представлен одной привязкой к дорожному графу,
подъезд к ней — временем при 15 км/ч. Облачная или площадная модель населённого
пункта этим изменением не вводится.

Индекс остаётся `100 × 2^(−t/2)` с временем в часах. В режиме нагрузки `t`
получено по сети с назначенным потоком и средним ожиданием. Отсутствие пути
даёт нулевой балл, отсутствие привязки — неизвестный результат.

Методика точечной очереди согласуется с определением перегрузки как превышения
спросом доступной способности в [материалах FHWA о заторах](https://ops.fhwa.dot.gov/congestion_report/chapter2.htm).
Это не калибровка наших значений: параметры 50%, 1800 и длительность являются
допущениями проекта. Общие сведения о постоянном притоке и обслуживании
приведены в [Traffic Flow Theory, глава 9](https://www.fhwa.dot.gov/publications/research/operations/tft/chap9.pdf).

## Сохранение и экономика

До выдачи успешного результата расчёт атомарно сохраняется в
`GRAPH_DIR/connectivity-results/<calculation_id>.json`. В Compose это постоянный
том `plexus_runtime`. Сохраняются время расчёта UTC, версия графа и метода,
закрытые OSM ways, все допущения, пары, потоки и очереди. Это неизменяемый снимок;
новый запуск получает новый ID. ID передаётся в историю чата из таблицы, даже
если ответ модели его не повторяет. Перезапуск процесса не удаляет расчёт.

`manage_calculation(kind=status, calculation_type=connectivity, calculation_id=...)`
читает компактное представление снимка; `detail=full` возвращает все исходные
поля, включая OSM IDs. `recent` возвращает до 20 последних расчётов связанности
вместе с доступными региональными расчётами; глобальный последний результат
нельзя автоматически считать результатом текущего разговора.

`manage_calculation(kind=connectivity_economics, calculation_id=...,
value_of_pcu_hour_rub=500)` умножает сохранённые потери времени транзитного потока
на явно условную стоимость приведённого автомобиле-часа. 500 рублей — пример
составной ставки, **не средняя зарплата и не наблюдаемая стоимость перевозки**.
Применять её следует только при разрешении пользователя моделировать допущения.

Потери времени считаются по изменению времени транзита между подходами к закрытию,
умноженному на перенаправленный поток и длительность. Они могут отличаться от
изменения времени поездки между населёнными пунктами. Денежный результат
охватывает только время этого потока: без потерь фонового движения, топлива,
стоимости груза и ВРП. При необслуженном потоке оценка неполна, а не равна нулю.
Обычный расчёт без `traffic` монетизировать этим инструментом нельзя.

## Проверка 11 ноября 2026 года

На одной паре Кочубеевское — Невинномысск закрыты OSM ways `37787244` и
`133175822`. При допущениях по умолчанию переносимый поток одного направления
составил 1800 приведённых авто/ч; он полностью назначен на два объезда.
Очередь к концу часа — около 638 приведённых авто. Время выбранной пары
изменилось с 19,83 до 24,76 минуты; это отличается от среднего времени
транзитного объезда между подходами к мосту — 46,50 минуты.

Условные потери времени транзита — 1345,30 приведённого автомобиле-часа.
При иллюстративной ставке 500 рублей за такой час получается около
672,65 тыс. рублей за заданный поток и период. Это не полный ущерб от
закрытия моста и не наблюдённые потери.

[Машиночитаемый протокол](results/traffic-diversion-validation.json) содержит
версии, точные значения, допущения и область проверок. Число дорожных примеров
равно одному: это проверка исполнения, а не транспортная калибровка. Отдельно
проверены сохранение потока, рост очереди с длительностью, отсутствие объезда,
выбор местного пути независимо от транзита, чтение после перезапуска и два
хода через протокол инструментов. Платная языковая модель не вызывалась.
