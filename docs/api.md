## Где находится контракт?

[OpenAPI](../backend/openapi.json) — полный контракт; `/docs` доступен при локальном запуске backend. Типы интерфейса генерируются из него.

| Метод и путь `/api/v1` | Назначение | Параметры |
| --- | --- | --- |
| GET `/health` | Состояние сервиса | Нет; не доказывает наличие каждого экспорта |
| GET `/regions` | Региональные показатели | `season=all/summer/winter`, `network_mode=road/multimodal` |
| GET `/regions/{id}` | Карточка региона | Те же сезон и режим |
| GET `/regions/{id}/links` | Исходные ручные связи | Сезон, вид транспорта |
| GET `/regions/{id}/settlements` | Страница пунктов | Поиск, сортировка, limit/offset |
| GET `/links` | Связи с координатами | Не вычисляет маршруты национального графа |
| GET `/index` | Состояние подключённых индексов | Метаданные компонентов |
| GET `/scenarios` | Каталог сценария индекса | 180 городов-рынков, версии матриц |
| POST `/scenarios/evaluate` | Пересчёт индекса с новыми связями | Сценарий road/summer/winter, версии, links (до 5); концы связи: опорный город или ОКТМО населённого пункта |


Ответ содержит исходные и изменённые поездки, суммы движения и ожидания, рёбра маршрута, разницу, статусы и допущения. `null` не заменяется нулём. Ограничение частоты 1–28 относится к вводу первой версии; исходное значение за границей сохраняется, но не редактируется.


## Как различать ошибки и результаты?

| Код/статус | Смысл |
| --- | --- |
| 409 | Версия опыта устарела; загрузить входы заново |
| 422 | Некорректный сезон, частота, связь или повтор изменения |
| 503 | Не хватает входов либо артефакт повреждён |

Чтение кэшируется в процессе. Для замены экспортов нужен перезапуск backend. Запросы не записывают национальные данные и не обращаются к платным моделям.

Концы маршрута взяты из прямого расписания; координаты остановок неизвестны, поэтому линии на карте не рисуются. Частота не преобразована в рейсы за неделю и не подменяется допущением. `season=all` установлен только для 601 маршрута, у которого все строки прямого расписания имеют период «круглогодично»; остальные 52 имеют неизвестный сезон и видны при выборе всех сезонов.

Архивы обслуживаются фронтендом по `/datasets/stavropol-*.zip`, содержат подготовленные данные и описание первичных источников. OSM не превращён в маршрутизируемый граф, адреса помощи не геокодированы, индексы не пересчитывались. Экономические показатели и население совпадают с новым региональным срезом. Национальные индексы импортированы из feat/model-validation и относятся к её зафиксированному набору входов. Локальные автобусные маршруты добавлены к каталогу, но ещё не включены в этот расчёт.


## Потоковый чат карты

`POST /api/v1/chat` принимает вопрос, историю и контекст карты. Возвращает поток
`application/x-ndjson` с событиями `status`, `delta`, `table`, `chart`, `map`, `done`, `error`.
`table` содержит реальные строки инструмента, `chart` — идентификатор таблицы и колонки.
Контракт генерируется в OpenAPI. Авторизация остаётся на сервере; по умолчанию
чат выключен. Запуск, ограничения и протокол: [чат карты](chat.md).

`GET /api/v1/regions/{region_id}/sensitivity?season=summer&network_mode=road`
возвращает базовый Hansen и три точки чувствительности при масштабах времени0,5 / 1 / 2.
Поля `kind=uniform_time_sensitivity`, `graph_recomputed=false`, версии и допущения
отличают результат от расчёта эффектов изменения рёбер графа. Нет данных —503, неизвестный
регион —404. Использует ту же реализацию, что инструмент агента.


## Локальный дорожный граф

При `GRAPH_DIR=/absolute/path/to/data` карта, сравнение регионов и расчёт используют
DuckDB и Parquet одного снимка data-20261107. Без настройки графовые endpoints отвечают
ошибкой недоступности. Источники не изменяются.

- `GET /api/v1/road-graph?west=&south=&east=&north=&zoom=`: сокращённые рёбра в окне,
  идентификаторы OSM ways, классы и скорости; LOD только для отображения.
- `POST /api/v1/road-scenarios`: `{region_id, scenario, changes:[{way_id,speed_factor}], links:[...]}`.
  Сценарии `road`, `summer`, `winter`; множитель0 закрывает дорогу,1 оставляет,1.2 увеличивает
  скорость на20%. Изменяется весь OSM way, максимум50 объектов. Возвращается job, не прогноз.
  `links` (до 30) удаляет или добавляет связи: `{action: add|remove, network: intercity|local,
  mode, source, target, hours?}`. `intercity` — ж/д (`rail`) и авиа (`air`) между 180 рыночными
  городами, концы — названия городов, `target="*"` при удалении убирает все связи вида у города.
  `local` — сезонные `air`, `river`, `ferry`, `winter_road`, `ice_crossing`, `pontoon_bridge`
  между населёнными пунктами (ID точек), есть только в `summer`/`winter`. Добавление требует
  `hours` в (0,72]. Удаление отсутствующей связи отклоняется422. Нужны `changes` или `links`.
- `GET /api/v1/transport-links?network=&place=&scenario=&mode=`: существующие связи снимка
  для выбора концов; межгородские часы — время в пути без пересадки (+1 ч ж/д, +2,5 ч авиа
  добавляет модель), местные — с учётом ожидания.
- `GET /api/v1/road-scenarios`: последние20 расчётов, в том числе запущенные агентом.
- `GET /api/v1/road-scenarios/{job_id}`: статус, прогресс, проверенные до/после, изменение,
  население, нормировка, число рёбер и измеренное время.
- `DELETE /api/v1/road-scenarios/{job_id}`: отмена на ближайшей границе этапа/поиска.

Один расчёт выполняется за раз; другой запрос отклоняется422, идентичный активный запрос
возвращает существующий job. Сохранённые завершённые результаты восстанавливаются после
рестарта. При несовпадении контрольной базы job завершается `baseline_mismatch` без прогноза.

- `GET /api/v1/road-graph/locations?query=&region_id=`: поиск населённых пунктов
  и их настоящих узлов привязки; непривязанные пункты возвращают `node=null`.
- `POST /api/v1/road-connections`: `{region_id,source_node,target_node,travel_hours,money?}`.
  Добавляет одну гипотетическую двустороннюю связь к базовой сети, возвращает job.
  Узлы берутся из поиска или ответа дорожного графа. Время положительное, не более 72 часов.
  `money`: `{origin_point_id,market_city,trips_per_year,rub_per_hour,capital_cost_rub?,annual_operating_cost_rub?}`.
  Результат содержит `routing_method=single_edge_delta`, изменение Hansen и при заданных
  допущениях условную стоимость сэкономленного времени. Если исходная поездка недостижима,
  денежная оценка отсутствует. Исходный граф не изменяется.

Ответ графа содержит `detail` с отображаемым классом дорог. На малом масштабе скрываются
целые младшие классы, без случайной выборки участков. Пересекающие окно длинные рёбра
включаются даже при обеих вершинах вне окна. Сжатие HTTP применяется только к этому
ответу, не к потоковому чату.


## Автоматический анализ дорог

Все пути имеют префикс `/api/v1`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/road-analyses` | Начать анализ региона: `criticality` или `improvement` |
| GET | `/road-analyses` | Сохранённые анализы |
| GET | `/road-analyses/{id}` | Статус и проверенные результаты |
| POST | `/road-analyses/{id}/cancel` | Остановить с сохранением результатов |
| POST | `/road-analyses/{id}/continue` | Проверить следующую порцию |
| GET | `/road-analyses/{id}/results/{way_id}` | Геометрия и изменения по населённым пунктам |

Параметры и обязательные поля ответа закреплены в OpenAPI. [Метод и ограничения](road-analysis.md).

Поток `/api/v1/chat` включает событие `calculation`: `calculation.corridor` содержит
геометрию именованного участка, а `calculation.job_ids` связывает карточку с заданиями
`/road-scenarios/{job_id}`. Событие отправляется после постановки закрытия в очередь;
результат и статус запрашиваются независимо от завершения ответа модели.

## Дополнительные ж/д и авиасвязи

`Mode` включает `rail`. `LinkResponse.is_model` отличает модельные пары от записей источников; у конечных пунктов добавлены nullable `lat` и `lon`. `GET /api/v1/regions/{region_id}/links?include_unknown=true` включает записи с неизвестным сезоном вместе с выбранным сезоном. Подробности и ограничения: [транспортная сеть](transport-network.md).

Результат новой дорожной связи содержит `settlement_effects`: до 30 пунктов выбранного
региона с наибольшим улучшением (`point_id`, `before`, `after`, `delta`). Поле
`affected_settlements` сообщает полное число улучшенных пунктов. Значения получены
из общего графового расчёта, включая транзит через новую связь; таблица не ограничивает
расчёт только концами. Старые сохранённые задачи могут не содержать детализацию.

`GET /api/v1/airports` возвращает каталог координат аэропортов, происхождение данных и привязки городов с методом и расстоянием. [Правила сопоставления](transport-network.md).

Событие чата `analysis` содержит `analysis` с полями `AnalysisResponse`. Оно связывает
сообщение с опрашиваемым заданием `GET /api/v1/road-analyses/{analysis_id}`.
Для комментария к завершённой порции `POST /api/v1/chat` принимает необязательный
`analysis_id`. Поле `prompt` остаётся обязательным по общему контракту, но сервер
заменяет его инструкцией интерпретации сохранённых результатов и очищает историю.
Запрос не регистрирует инструменты модели. Незавершённый или несовместимый расчёт
возвращает событие ошибки `chat_analysis_not_ready`, недоступное задание:
`chat_analysis_unavailable`. Новых расчётов этот запрос не запускает.

## Сравнение потенциальной доступности

`GET /api/v1/regions/{region_id}/accessibility?half_life=2` возвращает две сезонные
строки завершённого расчёта, версию исходного снимка, общую нормировку, признак
`source_current` и национальные счётчики известных частот. Допустимые полупериоды:
2, 4, 8 часов. `scheduled_index=null` означает отсутствие точного расчёта по расписанию.

Неизвестный регион возвращает 404, неподдерживаемый полупериод 422,
отсутствующий или неполный расчёт 503. Сохранённый снимок может
быть старше рабочего графа; такие данные явно помечены, сравнение внутри него остаётся
на одной базе. [Метод и воспроизведение](potential-accessibility.md).

## Экономическая оценка сценария

`GET /api/v1/road-graph/markets` возвращает названия расчётных рынков для выбора направления.
`POST /api/v1/road-connections` и `POST /api/v1/road-scenarios` принимают необязательный
`appraisal`: пассажирские и грузовые потоки с источниками, три сценария множителей,
стоимость строительства и содержания, горизонт, год цен и реальную ставку дисконтирования.
Параметры проходят одинаковую доменную проверку для HTTP и инструментов агента.
Поля и единицы описаны в OpenAPI и [методике](economic-appraisal.md).

Задание возвращает `appraisal_assumptions`; после успешного расчёта появляется
`appraisal_result` с тремя сценариями, пассажирским временем до/после, годовым эффектом,
дисконтированными выгодами и затратами, NPV, BCR и годом покрытия затрат.
`status=incomplete` внутри оценки означает отсутствие времени для выбранных поездок;
общая денежная оценка тогда `null`. Ошибки параметров дают422. Расчёт оценивает только
введённые потоки; значения не выводятся из изменения Hansen или населения.

## Карточки пересчёта дороги в чате

Инструмент `recalculate_road_index` отправляет событие `calculation` после создания
задания. `CorridorCalculation.changes` содержит исходные `way_id`, `speed_factor` и заданные
необязательные изменения профиля дороги.
Пустой или отсутствующий список сохраняет отображение прежних карточек закрытия.
Геометрия выбирается по всем указанным OSM ways, независимо от окна карты.
Карточка читает прогресс и результат через существующий `GET /api/v1/road-scenarios/{job_id}`.
`road_calculation_status` также возвращает карточку изменения дороги без повторного расчёта.
Если идентификатор утрачен в старом разговоре, `recent_road_calculations` находит последние
20 заданий с их регионом, сезоном и параметрами.

## Профиль дороги и грузовые маршруты

`RoadChangeInput` сохраняет `way_id` и `speed_factor`, у которого значение по умолчанию 1.
Дополнительные необязательные поля: `lanes_total` от 1 до 32, `highway`, `surface`,
`speed_kmh` больше 0 и не более 200. Класс и покрытие проходят доменную проверку.
Любое изменение профиля с `speed_factor`, отличным от 1, отклоняется422.

```json
{
  "region_id": "42000000",
  "scenario": "road",
  "changes": [{"way_id": 101, "lanes_total": 4}]
}
```

Пример показывает форму запроса; идентификаторы региона и дороги должны браться
из настоящего атласа и ответа графа. Поля профиля не изменяют исходные данные.
Результат содержит `road_cost_method` и `road_cost_notes`; отсутствие подтверждённого
часового потока не заменяется предполагаемой интенсивностью. Подробнее: [дорожная модель](road-capacity.md).

В `appraisal.freight` необязательные `origin_point_id` и `market_city` включают расчёт
времени и пробега по дорожному графу. Оба пункта требуются вместе. Поля `before_hours`,
`after_hours`, `before_km`, `after_km` для этого режима могут быть `null` и не служат
маршрутными доказательствами. Без OD-пунктов эти четыре значения обязательны и
должны быть конечными неотрицательными числами.

Оценка с грузовыми OD-направлениями возвращает `conditional_flow_appraisal_v2`,
`freight_travel`, `unresolved_freight_flows` и `freight_routing_scope`. При недоступном
грузовом маршруте общая оценка `incomplete`, денежные итоги отсутствуют. Ограничения
грузовика не подтверждаются. Годовые OD-потоки не используются как дорожная часовая нагрузка.

### Таблицы связанности в чате

События потока `table` поддерживают заголовки `connectivity_summary` и `connectivity`.
Сводка содержит баллы до/после, изменение и число потерянных пар. Попарные строки
содержат конечные пункты, часы пути, баллы и статусы `reachable`, `unreachable`,
`unbound`. `null` сохраняется как отсутствие данных. Поле `source` вида
`model:selected-settlements-road-v1:<graph_version>` обозначает расчётный снимок
и не отображается как HTTP-ссылка. История чата сохраняет оба типа таблиц.

## Национальные стресс-тесты дорог

| Метод и путь | Результат |
| --- | --- |
| `POST /api/v1/road-stress-tests` | Задание для `way_ids`, необязательный `parent_id` объединяет закрытия |
| `GET /api/v1/road-stress-tests` | Последние сохранённые задания |
| `GET /api/v1/road-stress-tests/{job_id}` | Состояние, прогресс, покрытие и сводки регионов |
| `DELETE /api/v1/road-stress-tests/{job_id}` | Отмена вычисления, сохранённые данные остаются |
| `GET /api/v1/road-stress-tests/{job_id}/impacts` | Пункты, фильтр `region`, пагинация `offset/limit`, до 200 строк |
| `GET /api/v1/road-stress-tests/{job_id}/geometry` | Геометрия закрытых OSM ways |
| `POST /api/v1/road-stress-tests/{job_id}/routes` | Пара `origin/destination` из ID пунктов, два пути с временем и расстоянием |

Для выборки видимой области `/impacts` принимает все четыре поля `west`, `south`, `east`, `north`.
Частичные или некорректные границы отклоняются. До завершения задания список последствий пуст;
это промежуточное состояние, не свидетельство нулевого эффекта. Сводка завершённого задания
остаётся доступной после смены графа, но геометрия и новые маршруты требуют совпадения версии.
Контракт возвращает `unbound` для отсутствующей дорожной привязки, `unreachable` для отсутствующего
пути, `reachable` для найденного пути. В двух первых случаях время и километры равны `null`.

Контекст чата принимает `road_way_ids`, `stress_job_id`, `stress_point_id`. Событие `stress_test`
несёт задание и необязательный `stress_route`. [Метод и проверенные примеры](road-stress.md).

### Краткие последствия перекрытия

`GET /api/v1/road-stress-tests/{job_id}/summary?region=...` возвращает `StressSummary`:
ID/версию/статус, число закрытых ways, выбранный регион, покрытие снимка и `totals`.
В `totals`: `affected_points`, `exposed_population`, `isolated_points`,
`isolated_population`, `max_delay_minutes`, `affected_regions`. До завершения `totals`
равен `null`; завершённый результат без последствий содержит нули. Неизвестный ID
отклоняется как `invalid_query`. Пустой регион означает совокупность затронутых регионов.

Региональная сводка `GET /api/v1/road-stress-tests/{id}/summary?region=...`
принимает точное название или ID региона и возвращает его название в `region`.
Дополнительное поле `consequences` доступно после завершения задания при выборе
региона; иначе `null`. Оно содержит пороги охвата задержек, изменения ближних
связей, города назначения и примеры до/после. Метод:
`saved_road_closure_consequences_v1`; [определения](road-stress.md).

### Автоматическая интерпретация расчёта

`POST /api/v1/chat/calculation-review` использует NDJSON-поток чата. Поле
`calculation_review` содержит `scenario_ids` и/или `stress_ids`; числа результата от клиента
не принимаются. Все задания должны быть завершены, отменены или ошибочны, причём хотя бы
одно должно иметь результат. Запрос без `calculation_review` получает HTTP422. Недоступные
или незавершённые данные возвращают ошибку потока, без обращения к модели. Обработчик
сохраняет локальное ограничение Origin и не предоставляет модели инструменты.

### Название диалога

`POST /api/v1/chat` принимает необязательный `title_requested` с исходным значением
`false`. При значении `true` и пустой истории агент может отправить событие
`type=title` с названием в `text`, не длиннее 80 символов. Название передаётся отдельно
от текста ответа. Запросы с историей, `analysis_id` или `calculation_review` не запускают
создание названия. Клиент сохраняет первое название и игнорирует попытки заменить его.

### Индекс и развитие сети с расчётным трафиком

`POST /api/v1/traffic-jobs` принимает `bounds` в порядке запад, юг, восток, север,
точное название `region` либо две записи `places`. Допущения `demand_multiplier`,
`pair_flow` и `max_projects` ограничены схемой OpenAPI.
`GET /api/v1/traffic-jobs/{job_id}` возвращает сохранённый прогресс, региональные
индексы, проверенные варианты и геометрию карты.
`POST /api/v1/traffic-jobs/{job_id}/cancel` останавливает работу на контрольной точке;
`GET /api/v1/traffic-jobs` возвращает краткий список последних заданий.

Превышение допустимого размера территории даёт явную ошибку. Для расчёта нужны
жилые объекты в ClickHouse и настроенный кэш графа. Чат передаёт событие `traffic`,
а `calculation_review.traffic_ids` запрашивает объяснение завершённых результатов.
## Как вызвать расчёт нормативной доступности?

| Метод и путь `/api/v1` | Результат |
|---|---|
| GET `/normative/criteria` | Девять критериев с актом, редакцией, единицами и режимом |
| GET `/normative/criteria/{criterion_id}/facilities` | Объекты из базы с источниками адреса и координат |
| GET `/normative/criteria/{criterion_id}/latest` | Последний сохранённый расчёт или null; снимок может быть старше текущих источников |
| POST `/normative/assessments` | Исходный и сценарный охват, строки пунктов, версия графа и сохранённый `run_id` |

Тело расчёта: `{"criterion_id":"N05","closed_way_ids":[]}`. Допускается до 20 OSM way ID. Неизвестный критерий или дорога вызывает ошибку валидации; отсутствие объектов или нужной транспортной модели — 503 `data_unavailable`. Результат включает неопределённые случаи, которые не превращаются в доказанную недоступность. [Методика и запуск](normative-accessibility.md).

Пешеходные N04/N09 возвращают `distance_metres`, автомобильные режимы — `minutes`. Отсутствующее значение остаётся null. `uncertainty` содержит машинные причины неизвестного статуса; источник физической длины не подтверждает условия правовой применимости. Для N01/N02 целевая группа — прикреплённые взрослые: без её распределения `population=null`, `lower_percent=null`, статусы неизвестны, времена сохраняются.

Ответы нормативного модуля с большими таблицами сжимаются gzip при поддержке клиентом. В пользовательском интерфейсе результаты разбиты на страницы; сервер сохраняет полный снимок строк.


Normative N07 rows also freeze nullable `threshold_minutes`, `territory_type` and
`territory_source_url`. Missing municipality context leaves the threshold null.
The library model keeps physical car minutes and unknown legal states when transport,
facility profile or entrance conditions are unconfirmed. Regional and institutional
libraries remain in separate stored profiles and are excluded from local N07 targets.


N03 requires `fire_profile: {speed_kmh, assumption}` on assessment requests. No speed
is inferred. The speed is finite and in(0,200]; the assumption has8–500characters.
The profile is returned in assessments and frozen in run storage. Other criteria
reject fire parameters. Missing parameters produce the existing validation error422.
N03 routes run from the depot candidate to the origin/call location. Stored minutes
remain conditional, with unknown legal status and explicit vehicle/readiness reasons.


Normative assessments expose `saved_at` as an aware UTC timestamp with millisecond
precision, read from the run metadata. POST and latest GET return the same timestamp.
`graph_fingerprint` is SHA256 of the UTF8 `graph_revision` descriptor; it is a compact
reference to the stored revision, not a binary graph content checksum. The original
revision descriptor remains available for replay. Historical legal source displays use
the saved criterion, independently of catalog updates.


N04/N09 возвращают `rule_sets`: группы правовых проверок с `rule_id`, применимостью, результатом, причиной, единицей, выбранным пределом, возможными пределами и источниками. Строка связывается с группой через `rule_set_id`. Физическое расстояние остаётся в `distance_metres`. `not_regulated` и `not_applicable` являются отдельными состояниями; их население и число точек учитываются отдельно от числового знаменателя. Подтверждения методики должны относиться к версии сети и выбранному сценарию. Новые снимки имеют `model_revision=normative-v4`; правила старого v3 не пересчитываются при чтении.


Объекты нормативных услуг дополнительно возвращают nullable`published_on`: дату публикации карточки источника. `observed_at` остаётся датой чтения; при известной точности до дня сохраняется ISOдата без выдуманного времени. Оба поля замораживаются в `run_facilities`; исторические снимки без даты публикации возвращаютnull. Дата публикации не равнозначна подтверждению текущего обслуживания.


Строки N07 дополнительно сохраняют `territory_verification_status`, `municipality_code`, `territory_structure_source_url`. Статус `encoded_parent_2024_assignment_unconfirmed` означает условное декодирование входногоОКТМО по перечню2024, а не подтверждённую территориальную принадлежность. `territory_source_url` указывает перечень кодов, `territory_structure_source_url` — правило декодирования. Код и оба основания замораживаются вместе с исходными и сценарными строками. В прежних снимках новые поляnull; чтение не дополняет их текущим справочником.

Для N07 модель `normative-v5` возвращает nullable `qualification_as_of` в ответе расчёта и `latest`, а в строках nullable `qualification_source_url` и `qualification_observed_at`. При пустом реестре все три поля равны null. Время квалификации имеет часовой пояс UTC и точность до миллисекунд; оно не заменяет время сохранения `saved_at`. Источник подтверждения и дата наблюдения замораживаются вместе со строкой. Несогласованные контингенты или подтверждённые муниципальные условия дают `data_unavailable` до записи результата. Подтверждения не принимаются из запроса браузера: их проверяет отдельный импорт справочников.

Модель `normative-v6` поддерживает типизированные медицинские подтверждения для N01/N02. `AccessResponse` содержит nullable `catchment_source_url` и `threshold_source_url`; `threshold_minutes` хранит применимый подтверждённый порог точки. Исходный федеральный ориентир остаётся в `criterion.threshold`. Пустой реестр сохраняет неизвестное взрослое население, неизвестный статус и null в новых ссылках. Время решения, источник и дата подтверждения используют контракт v5. Сохранённые маршруты v3/v4/v5 воспроизводятся с прежней стоимостью без переквалификации условий.

Модель `normative-v7` добавляет обработку `FireFacts` для N03. Строки содержат nullable `travel_profile_source_url` и `measurement_method_source_url`, замороженные вместе с источником подтверждения и `qualification_as_of`. Входной `fire_profile.speed_kmh` принимает явное число в диапазоне `(0, 200]`; логические значения и числовые строки отклоняются с 422 до расчёта. Исходные целочисленные JSON-числа допустимы. Проверенный профиль должен точно совпадать по скорости и описанию. Рабочий пустой реестр сохраняет неизвестный нормативный статус и null в новых ссылках. Маршруты v3–v6 остаются воспроизводимыми без переквалификации условий.


`FacilityResponse` содержит nullable `source_sha256`: 64 строчных шестнадцатеричных символа хеша адресного первичного документа. Поле сохраняется в `run_facilities` и возвращается без подстановки текущего хеша в старые снимки. Оно не характеризует актуальность услуги или координаты. Импорт проверяет формат до открытия хранилища. Для пожарного PDF все 26 записей имеют один хеш и отдельную ссылку на физическую страницу документа.


### N03: выбор объектов назначения

`GET /api/v1/normative/fire-destinations` возвращает текущие адресные объекты N03 с координатами, источником, датой наблюдения, статусом положения и необязательным хешем. Рабочий ответ сейчас `[]`.

`POST /api/v1/normative/assessments` принимает `origin_basis`: `settlements` или `fire_objects`. При отсутствии поля применяется `settlements`; явные null, логические значения и прочие строки отклоняются с422. `fire_objects` доступен только для N03 и не подменяется населёнными пунктами при пустом реестре. Отсутствие объектов приводит к503 `data_unavailable`. Пожарный профиль остаётся обязательным для расчёта.

Ответ содержит `origin_basis`; пешеходные расчёты возвращают `residential_references`. Nullable поля строк: `origin_source_url`, `origin_observed_at`, `origin_source_sha256`, `origin_reference_status`. Они сохраняются вместе с результатом и не перечитываются из текущего реестра при восстановлении. Формат объектов, привязка и ограничения описаны в нормативной методике.


### Версия координатного источника

FacilityResponse содержит необязательные `coordinate_snapshot_sha256` и `coordinate_snapshot_url`. Они независимы от `source_sha256` адресного документа, проходят отдельную проверку и сохраняются в снимке учреждения. Пара требует известной геометрии и HTTPисточника; неполные или конфликтующие значения отклоняются до импорта. Старые снимки получают null, их происхождение не заполняется текущим каталогом. Версия ссылки может обновляться; точный использованный снимок определяется хешем.

### Региональные каталоги услуг

`GET /api/v1/normative/regions/{region_id}/catalog/{criterion_id}` возвращает объекты выбранного региона, `candidate_count`, категорию, источники и версии координат. Регион определяется пересечением координаты с сохранёнными границами, без подмены Курганской областью. Неизвестный регион или критерий отклоняется. Для этих каталогов `calculation_available=false`, `profile_verification=unconfirmed`: наличие OSM-объекта не подтверждает профиль услуги или соблюдение норматива.

`POST /api/v1/normative/regions/{region_id}/measurements/{criterion_id}` с `closed_way_ids` рассчитывает автомобильную поездку для N01/N02/N05/N06/N07/N08. Это физические измерения до кандидатных объектов, без нормативного порога; школы, остановки и пожарное реагирование требуют своих моделей и отклоняются. `GET` по тому же пути с `/latest` возвращает сохранённый снимок выбранных региона и услуги. `GET /api/v1/normative/regional-measurements/{run_id}/routes/{origin_id}?stage=baseline|scenario` восстанавливает проверенный по стоимости путь из снимка.

`GET /api/v1/normative/regions/{region_id}/indices/{criterion_id}` возвращает опубликованное основание, варианты порога, числовые исходную/сценарную оценки, знаменатель, количество неизвестных путей и ID физического снимка. `qualification=conditional_known_objects`, `legal_compliance_confirmed=false`. Отсутствие взрослого контингента оставляет медицинскую долю населения `null`. Нет регионального основания: `basis=null`, числовые массивы пусты. Неизвестный регион отклоняется.


Для пакетных региональных расчётов доступны `GET` и `POST /api/v1/normative/regions/{region_id}/measurements/{criterion_id}/receipt`. POST принимает тот же сценарий, что полный расчёт, сохраняет его и возвращает идентификатор, дату, версию графа, режим, число опорных точек, рассчитанных путей и учреждений. GET возвращает последнее такое подтверждение либо `null`. Строки маршрутов в ответ не входят. Полный endpoint измерений сохранён для просмотра данных.
